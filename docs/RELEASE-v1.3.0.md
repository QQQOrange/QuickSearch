## 一、横条的「实时折射」可以调刷新率了（新）

### 你报的问题

> 「滚动之后这个液态玻璃的效果没有跟随，相反就像是卡住了一样。」

### 根因：是我上一版限帧限过头了

v1.2.2 为了把空闲 CPU 从 27% 压下去，我把**实时抓屏**这一路限到了 **15 帧/秒**。
静止状态下看不出问题，但**滚动网页或放视频时**，背景每 66ms 才更新一次 ——
肉眼就是"慢半拍、卡住"。

那一版的判断错在两处：

- 我以为抓屏开销大，实测**主进程只占 0.2%**，真正烧 26% 的是 WebView2 的着色器重绘；
- "15fps 看不出滞后"是坐在静止页面上得出的结论，滚动网页时一眼就能看出来。

### 先量清楚代价，再决定默认值

你说过「能接受为美观增加的合理开销，但一定要合理」。所以我没有直接放开，
而是先给抓屏加了分段计时（`QS_GLASS_TRACE=1`），实测 1349 个样本：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| **BitBlt** | **7.0 ms** | **97%** |
| GetDIBits | 0.05 ms | 0.7% |
| BGRA→RGBA 转换 | 0.05 ms | 0.7% |

再单独基准 BitBlt 的**尺寸相关性**：

| 抓取尺寸 | 耗时 |
|---|---|
| **16×16（256 字节）** | **6.24 ms** |
| 852×176（600KB） | 6.24 ms |
| 400×300 | 6.25 ms |
| 1920×1080（8MB） | 12.5 ms |

**结论：抓屏有一次约 6ms 的固定开销，与抓取面积无关。**
这是 Windows 从「屏幕 DC」抓取的固有代价（要等 DWM 合成 / GPU 回读），
换 API 或减少内存拷贝都省不掉。所以抓屏频率**直接**换算成 CPU：

| 上限 | 抓屏占单核 |
|---|---|
| **30（默认）** | **≈19%** |
| 60 | ≈37% |
| 120 | ≈75% |
| 跟随显示器（本机实测 85 帧/秒） | ≈53% |

### 最终做法

- 新增设置项「**刷新帧率**」，四档：**30（推荐）/ 60 / 120 / 跟随显示器**，
  每一档后面都标了实测占用，由你按机器情况挑；
- **默认 30** —— 滚动、放视频都已看不出滞后，开销压在单核 19% 以内；
- 该设置只在「实时折射」打开时显示（关着时抓屏根本不跑，帧率不起作用）。

> ⚠ **没有保留 15 那一档**（你要求删掉）。它正是"卡住"的来源，留着只会让人误选。

### 顺带做的三条真优化

| 优化 | 实测效果 |
|---|---|
| 两条绘制循环**合并成一条**（原来各跑一遍、叠加出 180+ 次/秒） | 调用次数回到刷新率本身 |
| 抓屏的 GDI 资源**常驻复用**（原来每帧重建 DC + 位图） | 省掉每秒几十次对象创建/销毁 |
| 抓屏**零拷贝**（原来一块 600KB 像素被拷 3 次，改成 GetDIBits 直写输出缓冲） | WebView2 侧 CPU 69% → 38% |

## 二、快捷键引擎：选中应用就自动用它的图标（新）

你要求：

> 「快捷键引擎要增加一个功能，那就是当我选择了某一个应用的时候，就能够把
> 那个应用的图标作为软件里显示的图标。」

现在给快捷键引擎「绑定应用」时，选完那个程序，软件会**自动把它的图标抠出来
当作这个引擎的图标** —— 横条上一眼就能认出来，不用再自己截图、裁剪、上传。

### 两条取图路径（这是实测出来的，不是设计时就知道的）

| API | 能拿到 | 对 `.lnk` 快捷方式 |
|---|---|---|
| `PrivateExtractIconsW` | **256×256** 大图，不发糊 | ✗ **实测返回 0**（快捷方式里没有图标资源） |
| `SHGetFileInfoW` | 32×32（shell 默认档） | ✓ **有效**（shell 会去读快捷方式的目标） |

由于**你选应用时大多是选开始菜单里的快捷方式**，第二条不是冷门兜底、而是主路径之一。
所以顺序是「先试直读拿大图 → 失败退回 shell」。

### 两个有意的取舍

- **不覆盖你手动换过的图标**。自动取图是"省事"，你手动挑一张是"明确表达"，
  不该抢。想换回应用图标：用「恢复默认图标」清掉之后再选一次应用即可。
- **失败时静默**。有些程序确实没内嵌图标，这时引擎照旧显示字母徽标，不弹错打扰你。

图标会存成 PNG 写进既有的图标机制里，所以**跨会话存活、跟着备份走、
能「恢复默认图标」**这些能力都自动具备。

## 三、修：点「立即重启」可能把程序整个关掉

你提到「同一时间只能开一个程序」，顺着查到这是**我在 v1.2.0 引入的真 bug**：

自动更新装好后点「立即重启」，流程是「先拉起新程序 → 再退出自己」。
而新程序一启动就会检查"是不是已经有一个在跑"——**此刻旧程序还没退干净、
单实例标记还被它占着**，于是新程序判定"重复启动"、**立刻退出**；旧的那个也退了。
结果：**桌面上一个都不剩。**

修法：重启时给新程序带一个"我是来接手的"标记，它会**等旧程序让位**再继续
（最多等 10 秒；超时就按新实例启动 —— 宁可冒一次多开的风险，也不能让你点了重启
却什么也起不来）。

真实进程验证（`qs_audit/instance_check.py`）：

- 普通地开第二个 → 它自己退出（单实例保护仍然有效）✓
- 交班式启动 → 旧程序退出后，**新程序活下来** ✓
- 两个不同测试标记的实例 → 可以并存（自动化测试靠这个）✓

### 走过的一个弯路（记下来免得重犯）

图标提取第一版跑测试直接 `STATUS_ACCESS_VIOLATION`（0xc0000005）把测试进程打挂。
原因是我在删除 DIB 对象**之后**才去读它内部的内存指针 —— 典型的
**释放后使用（use-after-free）**。修法是「先把像素拷出来、再删对象」，
这个顺序要求已写进代码注释。

## 安装

单文件，无需任何运行时，覆盖旧的 `QuickSearch.exe` 即可。
配置与图标都在 `%APPDATA%\QuickSearch`，不会丢。

> 已在用 v1.2.x 的话：打开软件就会看到更新提示（自动更新是 v1.2.0 起的功能），
> 点一下即可。**如果你正用 v1.2.2 且觉得滚动时玻璃卡顿，这一版就是为你修的。**
