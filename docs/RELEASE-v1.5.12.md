# v1.5.12 —— 修「点开更多引擎闪好几次」

> 用户报：「当我选择一段文字，然后点开更多引擎的时候，这时候页面会闪烁好几次，之后才开始稳定。」

不是一处毛病，是**三个互不相干的重绘源**叠在同一段时间里。逐帧对下来正好是
用户说的"好几次"。

---

## 根因一：每次打开面板都在重建整个列表

`togglePanel(true)` 调 `renderPanel(true)`，而缓存判断写的是：

```js
if (!focusFilter && sig === panelRenderSig && panelBody.childElementCount) return;
```

`focusFilter` 就是"这次是打开面板"。于是这一条永远不成立 —— **打开面板恰恰是
最不该重画的那一次**：内容跟上次收起时一模一样，重建收益为零。

代价是 `panelBody.textContent = ''` 之后要 createElement 几百个格子，这几十毫秒
里浏览器已经把"空面板"合成上屏了。视觉上就是一帧白闪。

**修**：指纹判断去掉 `!focusFilter`。指纹一样就只做三件事 —— 复位滚动、把光标
送回搜索框、同步分类高亮，**DOM 一个节点都不动**。

---

## 根因二：懒加载只填一节，窗口跟着长两次

面板是懒建的（滚到跟前才建格子）。原来只同步填 `panelFillers[0]`，其余交给
`IntersectionObserver`。

问题是：一节（5~35 格）撑不满 `.panel-body` 那 344px 的上限 → 面板先按"矮"的
尺寸被量一次 → 窗口按矮的摆好 → 观察器补填下一节 → 面板长高 → **窗口再改一次
尺寸**。表现就是画面跳两三次。

**修**：改成同步填到 `scrollHeight >= 344px` 为止（344 就是 `.panel-body` 的
`max-height`）。每个分类几毫秒，最多多花十几毫秒，换来面板高度第一帧就是终值
—— 观察器后面补的全落在滚动区里，不再改变整体高度，也就不会再动窗口。

---

## 根因三：玻璃抓屏把整个界面藏两帧（这条最狠）

抓屏用的是 BitBlt，会连自己的窗口一起拍进去。所以代码里有两条路：

```js
if (excluded) captureOnce(false);   // 已对抓屏隐身 → 直抓，舞台不动
else          captureOnce(true);    // 否则：藏舞台 → 等两帧 → 抓 → 恢复
```

`excluded` 只有开了「实时玻璃」才会被置 true（`startLive()` 里那句 `exclSet(true)`），
而 **`bar_glass_live` 默认是 `false`** —— 也就是说默认配置下 `excluded` 恒为 false，
每次抓背景都得先把整个舞台藏两帧，露出的是桌面。

面板一开一关，`glassRefit()` 要调**两次** `refresh()`（250ms / 700ms，为了兜
"慢一拍的摆位"）—— 就是两次明闪。

**修**：
- `onShow` 里补一次 `exclSet(true)`（放在 `applyConf` 之后，盖住它那次
  `stopLive` 的关闭）—— 横条一露头就对抓屏隐身，直抓，舞台全程可见；
- `refresh()` 在还没隐身时先补隐身再抓，补不上（系统 < Win10 2004，
  `WDA_EXCLUDEFROMCAPTURE` 不可用）才退回"藏舞台"，行为与从前一致。

> ⚠️ 行为变化：**横条显示期间对截图/录屏隐身**（收起时 `onHidden` → `stopLive`
> 会自动解除）。这是"不藏舞台"必须付的代价。如果你常录屏演示这个软件，觉得
> 看不到横条更难受，告我一声，可以改成只在面板开合那一下临时隐身。

---

## 顺带修掉的两个隐患

这两条是上面"不重建"改动**必须**配套的，否则会从"闪一下"变成"列表显示错了"：

1. **渲染指纹补上「最近使用」三要素**（`recentEngines` / `recentMax` / `barList()`）。
   这一栏原来不在指纹里 —— 用到它的是 `renderRecentSection`，画的是"用过的引擎
   减去横条上已有的"。不补进去，不重建就等于一直显示旧的那一栏。
2. **收起面板时把 DOM 的过滤状态也撤干净**（`applyEngineFilter('')`）。
   原来只清 `engineFilterText` 这个变量，被 `cell.hidden = true` 藏掉的格子原样
   留着 —— 反正"下次打开必然重画"。现在不重画了，不清就会把上次筛剩的半截
   列表端出来。
