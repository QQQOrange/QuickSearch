# Quick Search v1.5.8

**令牌输入框旁边多了「验证」和「保存」两颗钮：「验证」说清这是谁的令牌、额度多少、还剩几次；
「保存」等真的写进配置才回一句"已保存"。验证不落盘，可以先验再用。**

---

## 你要的东西

> 再就是个人访问密钥，希望有一个验证以及保存按钮

上一版加了令牌输入框，但填完能不能用、有没有存进去，只能靠"点一次检查更新"去试探 ——
这个反馈绕得太远。这次把它拆成两个各管一件事的动作：

| 按钮 | 做什么 | 会不会改配置 |
|---|---|---|
| **验证** | 拿输入框里**当前这串**去问一次 GitHub：账号是谁、额度多少、本小时还剩几次 | **不会** |
| **保存** | 把当前这串写进本机加密配置，等写完才回执 | 会 |

## 一、验证：先问一句，再决定用不用

### 为什么不用"检查更新"来验证

`releases/latest` 对**没权限的令牌**回的是 **404**，不是 401 —— 它和"这个仓库没发布过版本"
撞在同一个状态码上，分不清。而 `GET /user` 只认令牌本身：

- `200` + `login` → 令牌是好的；
- `401 Bad credentials` → 令牌坏的 / 过期了。

判据干净，不会出现"验证说坏了、其实是仓库问题"这种误伤。而且 `/user` 要的是最基本的
账号读取权限，细粒度令牌默认就带，不需要用户为了验证去多勾一个 scope。

### 报什么

状态行（`#githubTokenStatus`，`role="status"` + `aria-live`，读屏也能听到）：

```text
✓ 令牌有效：橙子（QQQOrange） · 细粒度令牌 · 额度 5000 次/小时，本小时还剩 4998 次
```

额度、剩余次数是从响应头 `x-ratelimit-limit` / `x-ratelimit-remaining` 读的；
令牌种类看有没有 `x-oauth-scopes`（经典令牌必带、细粒度令牌不带）。

失败时按类别给话，不是一律"验证失败"：

| 情况 | 提示 |
|---|---|
| 401 / Bad credentials | 令牌无效或已过期 —— 到网页上重新生成一个再粘过来 |
| 403（额度耗尽） | 接口限流了（这个令牌每小时的额度用完了）—— 约 N 分钟后恢复 |
| 403（其它） | 这个令牌没被允许读账号信息（HTTP 403）：<GitHub 原话> |
| 连不上 | 走 `ocr::explain` 翻成"网络不通 / DNS 解析不了 / 超时"这类人话 |

### 验证不落盘，这是故意的

```rust
#[tauri::command]
fn verify_github_token(token: String) -> Result<update::TokenCheck, String> {
    // 只读 token 参数，一个 set_setting 都没有
}
```

用户可以先把从别处抄来的令牌验一遍，确认能用再点保存 —— 不会出现"为了验证，反而把原来
好好的那个覆盖了"。探针里专门为这条立了断言：验证过后 `update_pending` 回报 `canAuto`
仍是 `false`（配置里还是空的）。

还有个小细节：**输入框一改动，上一次的"✓ 有效"就自动消失**。那段结论是给旧值的，
留着等于给一串改过的令牌背书。

## 二、保存：等写完再回执

```js
invoke('set_setting', { key: 'githubToken', value: v })
    .then(() => {
        TOK_SAVED = v;
        updSyncCanAuto(v);           // 顺带按同一口径重画「下载并安装 / 用浏览器下载」
        tokSay('✓ 令牌已保存到本机加密配置，接口额度 5000 次/小时', 'ok');
    })
```

- 存好之后按钮**变灰**（没有待保存的改动），一改又亮起来；
- 在输入框里按 **Enter** 也是保存（密码框回车最常见的期待）；
- 原来"失焦自动保存"照旧留着（`TEXTS` 里那条 `change → set_setting`），
  这颗钮是给"我要确认它真的存进去了"的人用的。

### 一个不好明说但必须处理的坑

点「保存」时，事件顺序是 **blur → change → click**。如果 change 里刷新了按钮状态，
而那时输入框的值已经等于已保存的值，按钮就会被 `disabled` 掉 —— 浏览器随后
**不再派发 click**，用户看到的就是"这颗钮点不动"。

所以 change 处理器只记账（`TOK_SAVED = value`），**不刷新**按钮的可用状态；
真正的刷新放在 click 处理完和输入时。代码里留了注释，免得以后"顺手优化"又踩回去。

## 验证

### 端到端：本地假 GitHub（第 ⑥ 组）

`QS_GITHUB_USER_API` 是新增的**仅测试用**逃生口（和 `QS_UPDATE_API` 同一类），
把「验证」的请求也指到本地假服务上，否则"令牌无效"这条分支只能靠手试。

本机实测（对最终发布产物 `v1.5.8`）：

```text
PASS  验证有效令牌：回报账号与额度
PASS    认得这是经典令牌（响应头带 x-oauth-scopes）
PASS    验证请求确实带了令牌
PASS    ⚠ 验证不落盘：配置里仍然没令牌，canAuto 还是 false
PASS  验证无效令牌：回一句人话（令牌无效/过期）
PASS    粘贴时带的空白/换行会被洗掉（和真正发请求同一套洗法）
PASS    日志里同样不出现令牌原文

结果：29 PASS / 0 FAIL
```

> 探针沿用 r157 的那套用例（启动自动检查、令牌进请求头、清空后走 302、被拒降级、
> 限流文案、隐私），这次只在末尾追加第 ⑥ 组，一共 29 条。
