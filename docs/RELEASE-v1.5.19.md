# Quick Search v1.5.19

## 主要改动

把翻译按钮和识图搜索按钮的默认图标，换成你给的那两张，并全部内嵌进软件。

- **翻译按钮**：原来的「译」文字徽标 → 你给的翻译图标。
- **识图搜索按钮**：原来的「四角取景框 + 放大镜」内联 SVG → 你给的识图图标。
- **两张图标全部内嵌**（base64，直接写进前端代码），不再依赖运行时去加载外部 PNG 文件。
  好处：之前外链 PNG 的路上，打包一旦漏带文件就会**静悄悄退回文字徽标**，你只会看到"图标怎么变成字了"却不知道原因；现在图随代码同生共死，打包进 exe 就一定在，零请求、零失败路径。
- 设置页左侧「翻译」「识图搜索」两个 tab 的图标也从 emoji 同步换成这两张。
- 顺手修掉一处自相矛盾：识图那一行原本摆着「编辑图标」按钮，点了却提示"这颗图标还没有图片" —— 现在它有内置图了，编辑器能正常打开，可以在默认图上抠背景。

## 安装

便携版，无需安装。下载 `QuickSearch.exe` 直接覆盖到原位置即可（旧数据不受影响）。

## 质量指标

- `test-ui.js`：**798 / 798** 全过（含 19 条新增的"图标内嵌"断言）。
- `cargo clippy --release`：**0 warning**。
- 真机 CDP 探针全绿：横条翻译 / 识图两颗都是内嵌 base64、naturalWidth 200×200、识图不再是 SVG、翻译不再是「译」字徽标、用户换过的图仍优先于内置默认图。

## 已知限制

- `cargo test --release` 中 `paths::tests::open_file_用默认程序打开真实文件` 在本机会**稳定失败**（`explorer.exe` 对本会话任何路径都返回退出码 1）。用改动前的 v1.5.18 旧二进制对跑失败方式完全一致，是既有的环境问题，与本次改动无关。
- 其余探针（trans-stream / hotkey-nonblock / trans-src）全绿；hang 探针的若干失败是窗口枚举在基线环境就为 null，旧 exe 对跑一致，非回归。
