# Quick Search v1.2.2 发布说明

> 发布日期：2026-10-19
> 上个版本：v1.2.1
> 这一版修一个**性能问题**：横条显示期间持续烧 CPU（实测 27% → 2%）。

---

## 起因：一次误报，但顺着查到真问题

你报「横条不能唤出」。排查中我先得出过两个**错误的**中间结论。
都记在这里，因为它们各自代表一类测量陷阱 —— 留着比抹掉有用。

### 误判一：以为"钩子坏了、程序卡死"

证据看起来很有力：你的进程日志**21 分钟零写入**，同时 CPU 持续涨。

**结论是错的。** 我注入一次真实的 Ctrl+C，钩子立刻响应：

```
show_bar: 前置合计 1ms → 已发事件，等前端量尺寸
⏱ 端到端 show_bar→窗口可见 = 14ms
after-show: visible=true
```

**14 毫秒**就弹出来了。日志零写入只是因为那段时间你没在操作。

你随后也确认了：当时是**远程桌面（ToDesk）**下操作，回到本地用真实鼠标就很顺利。
远程工具转发的是**注入事件**，低级鼠标钩子（`WH_MOUSE_LL`）看到的坐标与时序
和真实鼠标不同，划词判定会失准。**这是远程场景的固有差异，不是这个软件的 bug**，
本版本也没有针对它做改动（改不了 —— 那是系统层面的限制）。

### 误判二：A/B 对照自相矛盾

我先测出"实时折射开着 20%、关掉 0.6%"，随后重测又变成"关掉也 18~23%"。
两个结果互相矛盾，说明**至少有一次测量是脏的**。查下来原因是：

- 机器上同时跑着**多个测试实例**（我自己的 + 你的），
  而 `Get-Process msedgewebview2` 会把**所有**实例的 WebView2 子进程都算进来，
  CPU 全混在一起；
- 有些测量没有先清场，测到的是"启动期"而不是"稳定空闲期"。

**重新做了严格实验**（`qs_audit/idle_cpu_ab.py`），纪律写死在脚本里：
每次测量前清场并断言「启动前实例数 = 0、启动后 = 1」，
只统计目标进程**自己的** WebView2 子树（按父子关系递归，不按进程名捞），
配置写入后**回读校验**。

## 真正的问题：空闲时持续烧 27% CPU

严格单变量对照（两份配置**只差一个键**）：

| 配置 | 空闲 CPU |
|---|---|
| `bar_glass_live = True`（你的设置，实时折射） | **27%** |
| `bar_glass_live = False`（只改这一个键） | **0.5%** |

### 根因：两条渲染循环都按显示器刷新率跑，没有上限

我用 CDP hook 了 `requestAnimationFrame`，数**真实调用频率**
（`tools/bar-glass-idle-probe.js`）：

| 配置 | 横条显示期间 rAF 频率 |
|---|---|
| 实时折射关 | **≈94 次/秒**（本该 60） |
| 实时折射开 | **≈182 次/秒** |

`glass.js` 里 `raf`（重绘链）和 `liveRaf`（实时抓屏链）是**两条各自独立的
rAF 循环**，都按刷新率跑，于是叠加。

而横条是个**静止的小 UI** —— 画面只在三件事上变：弹出时的淡入（180ms）、
鼠标靠近的光斑、以及实时模式下背景刷新。**90~180fps 对这些毫无意义。**

### 修法：限帧，不是关功能

- **重绘链上限 30fps**。淡入期间**不跳帧** —— 那 180ms 是你唯一会盯着看的动画，
  跳帧能看出顿挫；淡入完成后才开始限。
- **实时抓屏链上限 15fps**。它每次要 BitBlt 一块 852×176 的区域、编码 600KB
  再走 IPC，开销比"重画一帧"大一个量级；而它的作用是让**背景**跟上桌面变化
  （比如背后在放视频），15fps 已经看不出滞后。
- 仍然用 `requestAnimationFrame` 驱动 —— 保持与显示器 vsync 对齐、
  标签页隐藏时自动暂停（这些是 `setInterval` 给不了的），只在回调入口做时间判断。

### 效果（同机、严格清场、配置回读校验）

| 配置 | 限帧前 | 限帧后 |
|---|---|---|
| 实时折射**开**（你的设置） | **27%** | **2.0%** |
| 实时折射关 | 0.5% | 1.7% |

**27% → 2%，降 93%。功能一个都没关。**

对你机器的实际意义：之前那个进程累计烧掉了 300+ 秒 CPU（风扇会响、笔记本会更费电），
现在这个开销基本消失。

## 验证

- 新增 `tools/bar-glass-idle-probe.js`：hook `requestAnimationFrame` 数真实频率，
  并验证「横条收起后循环确实停止」（实测收起后 1.0 次/秒）。2 项全过。
- 新增 `qs_audit/idle_cpu_ab.py`、`qs_audit/limit_check.py`：
  带清场断言 + 配置回读校验的 CPU 对照脚本，防止重蹈上面那两个测量陷阱。
- 圆角同心回归照旧全过（`tools/bar-radius-probe.js`，40 项）——
  限帧没有影响布局与渲染正确性。
- `cargo test` **276 / 276**；`cargo clippy --release` 0 warning。

## 只改了一个文件

`ui/glass.js`（限帧逻辑 + 两个阈值 + 注释）。Rust 侧一行未动。

## 安装

单文件，无需任何运行时，覆盖旧的 `QuickSearch.exe` 即可。
配置与图标都在 `%APPDATA%\QuickSearch`，不会丢。

> 已在用 v1.2.1 的话：打开软件就会看到更新提示（自动更新是 v1.2.0 起的功能），点一下即可。
