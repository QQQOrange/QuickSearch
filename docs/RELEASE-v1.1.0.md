# Quick Search v1.1.0

在 v1.0.0 基础上的一轮大改：**把图标抠图换成 AI**，并修掉一批实际使用中冒出来的 bug。

> ⚠ **许可变更**：v1.0.0 是 MIT（允许商用）。**v1.1.0 起改为
> [PolyForm Noncommercial 1.0.0](LICENSE)** —— 个人可自由使用、修改、分发，
> **不允许商用**。详见文末。

**程序本体 12.04MB**（不含任何 AI 模型），单 exe、免安装。

## 这版主要做了什么

### 1. 图标抠图彻底换成 AI（r80 / r80b）

用户原话：**「当前的完全用不了」**。原来那套纯颜色解混算法在
"主体与背景同色"的图上**数学上无解**（白 logo 落白底，方程欠定），
所以整条本地算法被删除，改为神经网络出 alpha。

- **四个模型可选、按需下载**（不打包进安装包）：

  | 模型 | 体积 | 平均耗时 | 10 个真实图标抠对 |
  |---|---|---|---|
  | **u2netp（推荐）** | **4.4 MB** | **63 ms** | **7~8** |
  | rmbg-quantized | 42.3 MB | 659 ms | 5~8 |
  | rmbg-fp16 | 84.1 MB | 437 ms | 5~8 |
  | rmbg-full | 168 MB | 496 ms | 5~8 |

  推荐 **u2netp** 而不是最大的那个 —— RMBG-1.4 是在**人像/商品**上训练的，
  它会删掉图标里的文字和底座。u2netp 只有 4.4MB 却更准。

- **模型与运行库都不入包**，点「下载」时才下（国内走 ModelScope / hf-mirror 镜像）
- **多镜像回退**：一个源不通自动试下一个（`huggingface.co` 在国内常有 DNS 污染）
- 下完做 **SHA256 校验** + 临时文件原子改名（取消/断网不会留半个坏文件）

### 2. 推理运行库改为**随模型一起下载**（r80g）

原来 `onnxruntime.dll`（11.84MB）是随程序分发的。现在：

- 安装包**省 11.8MB** —— 用到 AI 抠图的人才会下它
- 两个文件都落在 **`<程序目录>/抠图模型/`**
- **不需要重启程序**（见下方"两个坑"）

```
QuickSearch.exe
抠图模型/
├── onnxruntime.dll      11.84 MB（官方 69MB zip 解出来的）
└── u2netp.onnx           4.4 MB
```

### 3. 模型位置可查、可改、**自动迁移**（r80g）

设置页显示当前路径，并可：**打开**（资源管理器）/ **更换…** / **恢复默认**。

换位置时会**自动把已有模型迁过去**（先复制后删源 —— 跨盘 `rename` 会失败，
而复制失败时源还在）。迁移与"选目录"在同一步完成，避免出现
"配置指向新目录、模型还在旧目录"的夹缝状态。

默认位置就是**程序目录下的「抠图模型」**（跟着软件走，整个文件夹拷走就能带走模型）。

### 4. 涂抹修饰 —— 抠完可以手动修瑕疵（r80g）

用户原话：**「总有一些小瑕疵，通过涂抹把瑕疵涂掉……最好能够放大来涂，不然容易涂错」**。

- 两支笔：**擦除**（修瑕疵主力）/ **保留**（AI 误删主体时救回来）
- 涂在**结果图**上，**所见即所得**
- **放大 1~8×** 再涂；整笔撤销；重来（回到 AI 刚抠完的样子）；应用涂抹

### 5. 换了「手动补描」

旧的「手动补描」是在**原图**上涂，看不到抠完的效果 —— 用户反馈"没触发"。
实测链路其实是通的（探针 11/11 全过），真正的毛病在交互。
现在统一由「涂抹修饰」承担（见上）。

### 6. 设置页里也能直接用抠图工具（r80g）

用户原话：**「设置通用 ai 抠图这一框最好也有一个抠图按钮，那这样我也可以用
这个软件来实现抠图，搜完我就直接自己自定义地方保存」**。

现在可以直接挑一张图 → 抠 → 预览 → 另存到任意位置（**恒存 PNG** 以保透明）。
不涉及图标、不改任何设置。

### 7. 图标编辑器可以**临时换模型重抠**（r80g）

同一张图抠得不满意，下拉换个模型立刻重抠。只列已下载的模型。
**一次性**选择，不会污染你在设置里选的默认模型。

## 修掉的 bug

| # | 现象 | 真因 |
|---|---|---|
| 1 | **点一次「自动抠图」不出效果，要点两次才出成品图** | `img.onload` 在图片**已缓存/已 complete** 时**不触发**。探针实测：第一次点完 `imgComplete=true`、宽度已就绪，但 `imgHidden` 仍是 `true` —— 数据早好了，只是界面没显示。改为设完 `src` 立刻查 `complete`，不等事件 |
| 2 | **引擎库里搜一个引擎，出现多个同样的** | 不是渲染 bug，是**数据模型**：一个引擎可属多个分类（实测 777 行里 8 个重名，如「知乎」同时属知识/社交/新闻）。按分类浏览时各出现一次是对的，但**搜索结果是一份清单**，列三遍只会让人以为出错 → 搜索时按名字去重 |
| 3 | **开关打开后不生效 / 状态不同步** | 开关没进设置页那张**统一绑定表** `SWITCHES`，于是只改了控件、没写配置也没同步 `CONF` |
| 4 | **抠图功能默认该不该开** | 按用户口径改成：**默认关**。关着时点「换图标」直接替换文件，界面上**没有**编辑按钮 |
| 5 | 三个 RMBG 模型下载不了 | `huggingface.co` 在这台机器上被 **DNS 污染**（解析到 `2a03:2880:…:face:b00c:…`，21 秒超时）→ 改为多镜像回退 |
| 6 | AI 结果把主体内部掏空 | 第一版无条件信任 AI。改为**互补判据**：AI 说"背景"时还要本地连通性也同意（只有能走到图像边界的同色区域才算背景） |

### ⚠ 两个值得记下来的技术坑（都写进了代码注释）

**(a) 运行库能不能"随模型下载"，取决于一个 feature**

`ort` 不开 `load-dynamic` 时会在**编译期**静态链接，于是 dll 是
**进程启动期的硬依赖** —— 缺了它 exe 根本起不来。开了之后改成
**首次推理时**加载，这才谈得上"按需下载"。

> 我在验证这点时**连续给出了两次错误结论**：
> - "缺 dll 也能启动" ← 被 Windows 的**模态错误框**骗了（进程活着 ≠ 启动成功，
>   它在弹框等用户点"确定"）
> - "是硬依赖" ← 被**单例检查**骗了（日志 `another instance is running, exit`，退出码 0）
>
> 第三次才可信：进程存活 + 主窗口 `QuickSearchBar` + **WebView2 子进程 +2**。
> 教训：判断"程序起没起来"要看**有没有真的建出界面**。

**(b) `ORT_DYLIB_PATH` 的缓存会被"冻住"**

`G_ORT_DYLIB_PATH` 是 `OnceLock`，而它的初始化闭包**只读环境变量、不会 panic** ——
所以第一次（下载前）就把**错误的路径**永久缓存了。结果：dll 下好了
（`runtimeFile=true`）但 `runtime=false`，**只能重启程序**。

修法：**无条件**把该变量指到"将来会在的位置"，让缓存的就是正确路径。
实测同一进程内：先查 `false` → 放入 dll → 再查 **`true`** → 真能推理出图。

## 安装

1. 下载 `QuickSearch.exe`
2. 放到任意目录，双击运行（无需安装）
3. 首次运行会请求管理员权限 —— **这是必需的**：只有管理员进程才能把 Ctrl+C
   送进同样是管理员的程序（任务管理器、各类编辑器）。可在设置里关闭自动提权
4. 想用 AI 抠图 → 设置 → 通用 → AI 抠图 → 打开开关 → 点「下载」
   （会自动连运行库一起下好，**不用重启**）

**系统要求**：Windows 10/11 x64，WebView2 Runtime（Win11 内置；Win10 若缺失会提示）。

## 已知限制

- AI 抠图对**扁平图标的内部封闭区域**判断不稳（会把主体内部当背景）——
  用「涂抹修饰」或调「前景确信度」、或换个模型可解
- 部分游戏全屏独占时，全局钩子可能失效
- UIA 读不到选区的程序会退回「模拟 Ctrl+C + 读剪贴板」；若该程序禁用复制则无文本
- 识图「按图片地址搜」那两家需要自己填一张公网图片地址（软件不代传截图）
- 仅支持 Windows；macOS / Linux 未适配
