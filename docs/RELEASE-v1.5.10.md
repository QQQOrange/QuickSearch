## 一、导出：「加密导出」勾选框 + 隐私项强制

### 界面

`数据` 页按钮行最前面多了一个勾选框：

```html
<label class="exp-enc" id="exportEncWrap">
    <input type="checkbox" id="s-exportEncrypt">
    <span>加密导出</span>
</label>
```

规则（`syncExportCount` + `export::write_plain`）：

| 情况 | 结果 |
|---|---|
| 不勾、内容不含隐私 | 明文 JSON（和以前一样） |
| 勾了、内容不含隐私 | `qsEnc:1` 信封（AES-256-GCM + Argon2id） |
| **含隐私内容** | **强制加密**，勾选框自动勾上并 `disabled` |
| 该加密但本机没设备份密码 | 拒绝导出 + 一句话说明出路 |

### 「强制」是怎么判的

`export::needs_encrypt(items, data)`，两个条件都得满足：

1. 勾中的组里**有** `private` 标记的（`apiKeys` / `secrets` / `favorites` / `backupSettings`）；
2. 那个组**真的带了非空值**出来。

第 2 条不能省。只看"勾了什么"会把空内容也算成隐私 —— 勾了「个人访问令牌」
但本机压根没填，导出的文件里一个敏感字符都没有，还逼用户去设密码，是无谓的摩擦。
反过来只按"内容里有没有敏感键"判又太窄：`Group::private` 是声明，
以后给某个隐私组加字段，不该再回来改这里。

外加一道兜底 `contains_secret`：它看的是**值**，不是组的标记。万一某个组被误标
成非隐私，令牌仍然不会明文落盘。

### 为什么勾选框要"锁住"而不是"偷偷加密"

- 只偷偷加密 → 用户以为导的是明文，拿去当普通文件处理，打开一堆乱码；
- 只弹提示不锁 → 用户能取消勾选，"强制"就不成立；
- 锁住 + 明确写"强制加密" → 用户看得见发生了什么，也知道没得选。

前端按"勾了隐私组"锁，比后端（"隐私组里真有内容"）更保守一格。
保守的那一边只会多加密一次，不会漏。

## 二、导入：加密文件要输密码

### 以前的问题

v1.5.9 的做法是"拿本机备份密码悄悄试一次"。解不开就报一句「密码不对」，
可界面上**没有任何地方能输密码** —— 用户只能去「备份」页改密码，
而那会连累这台机器上所有其他加密备份。

### 现在分三步

```text
点「导入配置文件…」
  └─ 选文件（import_items）
       ├─ 明文        → 直接导入完成
       ├─ DPAPI 信封  → 直接导入（钥匙是 Windows 账户，问密码没意义）
       └─ 密码信封    → 发 qs://import-need-password
                          → 前端弹框（模态）
                          → import_with_password(password)
```

密码**只用于解这一个文件**：不写配置、不进日志、关掉就丢。
也**不会**去改「备份」页那个备份密码。

### 两个细节

**输错密码不关框。** `import_with_password` 失败时把路径**放回** `IMPORT_PENDING`：

```rust
Err(e) => {
    if let Ok(mut g) = IMPORT_PENDING.lock() { *g = Some(p); }
    Err(e)
}
```

不放回去的话，用户第二次输对也没用 —— 得重新走一遍「选文件」。

**错误显示在框里，不发 toast。** 用户正盯着密码框，toast 一闪就没了，
他还得猜是不是自己没点中。

键盘：Enter 提交，Esc 取消，点遮罩也是取消（都调 `import_cancel` 丢掉待导入路径）。

## 三、额度用量：「已请求 X 次 / 共 Y 次」

令牌输入框正下方多了一行常驻小字：

```text
● 本小时已请求 3 次 / 共 5000 次 · 还剩 4997 次
● 本小时已请求 2 次 / 共 60 次 · 还剩 58 次（匿名额度，填令牌可提到 5000 次/小时）
```

### 为什么走 `/rate_limit`

`/user`（「验证」按钮用的那个）是**计入额度**的。设置页每开一次就烧一次配额。
GitHub 明文规定 `/rate_limit` **不计入额度**，所以这一行可以常驻、可以频繁刷新。

`update::rate_state()` 只读响应头（`x-ratelimit-limit/remaining/reset`），不解析 body ——
body 的 `resources.core` 形状哪天变了，不该让这行整个崩掉。

### `used()` 用 `saturating_sub`

GitHub 偶尔给出 `remaining > limit` 的瞬时值（刚改配额、中间缓存），
普通减法会**下溢 panic**。单测钉住了这条。

### 刷新时机

- 打开设置页（`updInit`）
- 保存令牌后（额度 60 ↔ 5000 会变）
- 清除令牌后
- 每次「检查更新」回来（一次检查 = 一次 API 调用，额度确实动了）

### 查不到就藏起来

断网 / 被墙 / 接口变了 → `{ok:false}` → 整行 `hidden`。
宁可没有，也不要留一个几小时前的数字在那儿冒充"现状"。
