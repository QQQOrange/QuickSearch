# 优化版与原版对比说明

> 版本基准：原版 `QuickSearch.exe`（Tauri，v1.5.22）；优化版 `QuickSearch-lite.exe`（wry 重写，便携）
> 编写日期：2026-10-30
> 本文所有结论均来自同机实测或源码逐行比对，未实测的项目会明确标注「未测」。

---

## 0. 一句话结论

优化版与原版**共用同一套前端 `ui/`、同一套配置文件结构、同一套加密实现**，因此二者在数据层面完全互通：
原版产生的 `config.json`、`.QuickSearch` 备份、WebDAV 云端数据，优化版都能直接读取、恢复、再导出回原版使用。

差异集中在**分发形态**（体积、便携性）与**默认值取舍**（付费引擎兜底、图标来源），而非数据格式。

### 1.1 本次新增的功能（优化版独有）

**自定义图标自动导入**：便携版首次启动时，从「上一次安装的数据目录」只搬运 `overrides`（图标覆盖表）与对应图标文件。

- **输入**：候选源目录（`%APPDATA%\QuickSearch`、exe 上一级/上两级的 `Quick search data` 或 `QuickSearch`）
- **输出**：当前数据目录的 `config.json`（仅 `overrides` 字段被写入）+ `icons/` 下的图标副本
- **适用场景**：换机、换版本、便携版与原版并存
- **边界条件**：源配置解不开 / 无 `overrides` / `overrides` 为空 → 跳过并落标记，不做任何写入
- **异常处理**：图标文件缺失的条目**整条跳过**（宁可少导入，也不让前端拿到死路径）
- **幂等**：成功后写 `.icons-imported` 标记；用户「恢复默认」清空图标后不会被强行塞回
- **明确不迁移**：API Key、`ocr_multi`（付费引擎兜底）、语言、快捷键、热键 —— 避免静默产生费用

## 2. 界面与图标一致性

### 2.1 图标来源（这是本次问题的主因）

原版从未使用 `ui/data/icons/` 里的 png 作为最终显示图，**真实图标存在配置的 `overrides` 里（data URL）**：

| 键 | 原版实测值 |
|---|---|
| `@ocr` | data URL，8210 B |
| `百度` | data URL，9170 B |
| `Google` | data URL，11334 B |
| `知乎` | data URL，5350 B |
| `淘宝` | data URL，8754 B |
| `京东` | data URL，8646 B |
| `天猫` | data URL，20630 B |
| `豆瓣` | data URL，3486 B |
| `微信截图` | data URL，16306 B |
| `章鱼速贴快捷输入` | data URL，170734 B |

优化版此前是全新配置，`overrides` 为空，于是：OCR 按钮退化成「OCR」文字徽标，引擎退回内置 png —— 与用户自己的那几张**不是同一张图**。

### 2.2 修复后的一致性验证

| 项 | 原版 | 优化版（修复后） |
|---|---|---|
| `overrides` 条目数 | 10 | 10 |
| `@ocr` 图标字节数 | 8210 | 8210（完全一致） |
| 横条「OCR」文字徽标数量 | 0 | **0** |
| 横条图标加载失败数 | — | **0** |
| 图标文件 HTTP 200 比例 | — | **402/402** |

### 2.3 图标解析优先级（两版共用）

```
overrideIcons（用户/导入的图）
  > dirIcons（icons 目录里「文件名 = 引擎名」）
    > engines.json 的 iconFile（内置 png/svg/ico）
      > 字母徽标（首字 + 品牌色）
```

> 注：`dirIcons` 在便携版中始终为 0 条（它只扫用户数据目录），实际渲染由 `overrideIcons` 与 `iconFile` 两路承担。

### 2.4 仍存在的界面差异（未改动，按你「没换的维持原状」的口径保留）

- `淘宝（首页）` 用 `淘宝（首页）.ico`，与 `淘宝.png` 不是同一张
- `京东（首页）`、`天猫（首页）`、`豆瓣电影（首页）` 同理
- `百度知道/百科/文库/经验/地图/图片/新闻/汉语/网盘/学术/贴吧` 共 11 条用各自图标
- 123 条引擎无本地图标，走字母徽标（如「通」「M」）

## 5. 数据兼容性（同步 / 备份 / 加密 / 导入 / 导出）

### 5.1 源码级一致性（逐文件比对）

| 模块 | 行数 | 与原版差异 |
|---|---|---|
| `crypto.rs`（加密/解密） | — | **0 行（字节级完全一致）** |
| `export.rs`（明文导入导出） | 898 | **0 行** |
| `webdav.rs`（云端同步） | 1093 | **0 行** |
| `Config` 结构体字段 | 99 | **99 对 99，无缺失/无多余/无类型差异** |
| 备份函数集 | 20 个 | 函数名与集合完全一致 |

### 5.2 各功能输入输出 / 场景 / 边界 / 异常

#### （1）配置加密（本地）

| 项 | 内容 |
|---|---|
| 输入 | 明文 JSON |
| 输出 | `{"qsEnc":1,"kdf":"argon2id","salt":…,"nonce":…,"data":…}` |
| 场景 | 每次保存配置 |
| 边界 | 换机器/换 Windows 用户 → `backup.key`（DPAPI）失效 |
| 异常 | 解不开时进入 `LOCKED` 状态，**禁止任何写盘**，原文件原样保留，等用户填回备份密码 |

#### （2）备份（本地 / 云端）

| 项 | 内容 |
|---|---|
| 输入 | 当前配置 + 可选备份密码 |
| 输出 | `<备份目录>/config(YYYY-MM-DD HH-mm-ss).QuickSearch`；自动备份为 `config.auto(…).QuickSearch` |
| 场景 | 手动备份、退出自动备份、WebDAV 上传 |
| 边界 | 有密码 → 备份可跨机恢复；无密码 → 仅本机可解 |
| 异常 | 密码不符/缺失 → 明确报错「这份备份设了密码，但本机还没填」，**不写入任何数据** |
| 兼容 | `detect_backup_format` + `restore_accepts_both_backup_formats` 同时兼容新旧两种信封 |

#### （3）恢复

| 项 | 内容 |
|---|---|
| 输入 | 备份文件名（**仅文件名**，拒绝 `/ \ .. :`） |
| 输出 | 覆盖写入当前 `config.json`，返回提示语 |
| 场景 | 重装、换机、误配置回滚 |
| 边界 | 文件名必须落在备份目录内（防目录穿越）；备份密码必须已填 |
| 异常 | 文件不存在/格式不识别/密码错 → 返回中文错误，配置不变 |

#### （4）明文导入 / 导出

| 项 | 内容 |
|---|---|
| 输入 | 导出：键名列表；导入：明文 JSON |
| 输出 | 可读 JSON 片段（不含密钥类字段） |
| 场景 | 手工搬运单项设置、排障比对 |
| 边界 | `dirIcons` **只导出不导入**（导入侧无图标落盘实现），见 `export.rs` 明确注释 |
| 异常 | 非法键名/类型不符 → 逐项跳过并回报 |

#### （5）WebDAV 同步

| 项 | 内容 |
|---|---|
| 输入 | 服务器地址、账号、密码、开关（启动同步 / 退出上传） |
| 输出 | 远端 `<app>/config.QuickSearch` |
| 场景 | 多机同步 |
| 边界 | 令牌类字段「恢复时保留本机令牌」—— `restore_keeps_local_token_when_backup_has_none` 已覆盖 |
| 异常 | 网络失败 → 记录日志、保留本地数据，不阻塞主流程 |

### 5.3 迁移路径

```
原版数据目录（D:\...\Quick search data）
        │
        ├─ ① 直接指向：优化版用 QS_DATA_DIR 指向同一目录即可原地复用
        │
        ├─ ② 备份恢复：原版导出 .QuickSearch → 优化版「恢复」→ 得到全量数据
        │
        └─ ③ 便携共存：优化版首次启动自动导入 10 个自定义图标（本次新增）
                       密钥 / 引擎 / 快捷键不迁移，保持干净默认
```

## 7. 如何对照旧版逐项核验（可复现步骤）

1. **源码级**：分别提取两版 `Config` 结构体字段、`crypto.rs` / `export.rs` / `webdav.rs` 做 `diff`，应为 0 差异。
2. **配置读取**：把原版数据目录复制一份，用 `QS_DATA_DIR` 指向它启动优化版；能正常启动即证明解密与解析兼容。
3. **指纹比对**：分别在「原版数据副本」与「恢复后的新目录」上取同一组字段（本文第 6 节那 19 项），逐项比对。
4. **备份恢复**：原版产出的 `.QuickSearch` 放入备份目录 → 恢复 → 复核指纹。
5. **边界用例**：① 空密码恢复带密码备份；② 带 `..` 的文件名；③ 损坏的备份文件；④ 清空 `overrides` 后重启（验证不会被强行塞回）。
6. **回归**：`cargo test --release` 应为 393 通过 / 0 失败 / 2 忽略。

> 本次实测使用的探针脚本：`probe-regress.js`（图标全量校验）、`verify-restore.js`（跨版本恢复指纹比对）。
