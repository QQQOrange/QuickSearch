# Quick Search v1.4.3 发布说明

> 发布日期：2026-10-22
> 上个版本：v1.4.2
> 这一版只做一件事：**把"改设置时那一下卡顿"拿掉**，并附一份全盘审视报告。

---

## ① 修的是什么

你的设置页每次改一个开关，后端都要把整份配置重新加密写盘。而加密用的是
**Argon2id**（m=19 MiB, t=2）—— 它是故意设计得"很重"的抗暴力破解算法，
实测单次 **120~150 ms**，而且这段是在**持着配置锁**、在你点完开关那一瞬间花的。
连点五六个开关，就能明显感到发涩；同一时刻横条渲染、快捷键读配置都得排队等这把锁。

根因不是"不该用 Argon2"，而是**同一个密码反复算同一把钥匙**：
每次加密都换一个新盐 → 每次都重新派生。盐的职责只是挡彩虹表，
同一台机器、同一个密码、反复写同一个文件时换盐**没有任何安全收益**
（AES-GCM 的 nonce 每条都是新的，这才是真正不能重复的东西）。

## ② 改了什么

| 位置 | 改动 |
|---|---|
| `src/crypto.rs::encrypt` | 盐与密钥**进程内复用**（同一密码），每次仍生成**全新 nonce** |
| `src/crypto.rs::decrypt` | 按「密码 + 盐 + KDF 参数」缓存密钥 —— 启动时同一份 `config.json` 会被解不止一次，以前每次都重跑一遍 Argon2 |
| 换密码 | 立即失效、重新派生 + 换盐；**绝不会**拿旧密钥去加密新密码的内容 |

**加密强度一个都没放松**：Argon2id 参数不变、AES-256-GCM 不变、每条新 nonce 不变、
版本号仍进 AAD。改的只是"同一台机器上不必反复重算同一把钥匙"。

## ③ 效果

| 项 | 改前 | 改后 |
|---|---|---|
| 保存一次配置 | ≈ 125~155 ms | **< 1 ms**（首次仍付一次 KDF） |
| 启动时多次解密同一份配置 | 每份 120~150 ms | 第一份之后 ≈ 0 |
| 设置页连点开关 | 明显发涩 | 无感 |

## ④ 顺带：全盘审视报告

`docs/OPTIMIZATION-REVIEW-2026-10-22.md` —— 覆盖代码结构 / 功能健壮性 / 资源与性能 /
页面布局 / UI 视觉，按 P0~P3 列了 20 条问题（每条带文件位置、影响、具体改法）和一张
分五个阶段的路线图。几个结论先摘在这儿：

- **最容易拿的体积**：图标 2.63 MB（`ui/data/icons`），其中 3 个文件就占 500 KB
  （两个 256px 的 .ico 各 220~260 KB），而界面里最大只显示 28 CSS px。
  全部压到长边 96px，程序本体能小 **1.6 MB 左右**（约 -13%）—— 需要逐个目视验收，放在下一版。
- **最大的技术债**：`src/main.rs` 16,945 行、127 个命令挤在一个文件（占 Rust 代码 43%）。
  建议按域拆模块，纯移动、零行为变化。
- **最影响可诊断性**：前端 56 处 `catch(() => {})` 把 IPC 失败静默吞掉 ——
  之前那两个 bug（搜不到引擎、快捷键引擎不显示）都属于"静默失败"型。
- **已经做得不错、不必动的**：面板渲染分片 + 懒填 + 图标测量缓存、`pushLayout` 去重、
  异步批量日志、`panic=abort` 的取舍、Argon2 参数本身。
