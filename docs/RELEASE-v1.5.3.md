# Quick Search v1.5.3

**两个修复：① 划词取到的字不对（搜出一串垃圾）；② 窗口最大化后右边一大片空白。**

---

## 一、修：划词取到的字不对

你的反馈：

> 选中了 `马尾辫skill安装`，用横条中的谷歌搜索来搜索，就变成了 `《马尾辫 sk 泔安装、`

**不是引擎的锅，是取词**。链路是这样：

```
划词 → 编辑控件？没有 → UIA（系统无障碍接口）？浏览器/Electron 里**跳过**
     → 只能读屏幕上那块像素认字（OCR）→ 「马尾辫skill安装」被认成「《马尾辫 sk 泔安装、」
     → 原样喂给谷歌
```

为什么会跳过 UIA：Chromium 系（Edge / Chrome / 各种 Electron 应用）的 UIA 内容树
**唤不醒**（r34 实测，强制前台 + 双消息变体都不行），查询只会白等 1.5 秒。
所以这些程序里一直是"读屏幕认字"，而认中英混排的小字很不稳。

**现在的做法**：认完字之后再**校一遍** —— 模拟一次 Ctrl+C 把选区**原文**读回来
（剪贴板读完立刻还原），拿到精确文字就替换掉认错的那份。你在横条上看到的是：
条先弹出来（零延迟），半秒内文字被纠正，点引擎搜的是对的。

什么时候校：

| 场景 | 行为 |
|---|---|
| **浏览器 / Electron 里取词** | **一律校**（那里的 Ctrl+C 就是"复制选区"，安全） |
| 别的自绘程序（微信这类） | 只在**看起来就像认歪了**时才校：首尾多出落单的标点（只有 `《` 没有 `》`）+ 中间夹着 `sk` 这种碎字母片段，两条同时才算 |
| 取到的像网址 / 浏览器里划了一大段却几乎没认出来 | 照旧校（r98 的老规则） |

顺手补了一道安全阀：复核前先确认**前台还是原来那个程序**。不然你在那几十毫秒里
点了别的软件，我们会把**那个程序的选区**复制回来当成这次划词的文字 —— 比认错字
更难理解。

> ⚠ 代价说清楚：浏览器里现在每次划词都会多用一次剪贴板（约 30~80ms，看不出来，
> 但 Win+V 剪贴板历史里可能多一条）。觉得不值可以说一声，改成"只在可疑时才校"。

## 二、修：窗口最大化后右边基本全空

你的反馈：

> 要是窗口放到最大之后，右边基本全是空的

**实测**（无头 Edge + CDP 量的真几何）：

| 窗口宽 | 卡片宽 | 一行里「文字 + 开关」占 | **中间空白** |
|---|---|---|---|
| 1200 | 996 | 546 | 416 |
| 1600 | 1396 | 546 | **816** |
| 1920 | 1716 | 546 | **1136** |
| 2560 | 2356 | 546 | **1776** |

根子不是某一行没写好，是**内容列没有上限**：卡片跟着窗口无限拉宽，而 `.row`
用的是 `space-between`（文字靠左、开关靠右），中间就全空了。

现在：

1. **内容列有上限并居中**（1240px，宽屏 1480px）—— 任何窗口尺寸下都是一个
   正常宽度的设置页，不会越拉越散；
2. **窗口够宽（≥1300px）时，多卡片的分栏自动排成两列** —— 通用、外观、引擎
   这些页从"一列流水"变成两列，把宽度真正用起来；
3. **只有一个卡片的分栏**（帮助 / 关于 / 范围 / 抠图 …）仍然整宽铺开，
   不会变成"半列内容 + 半列空白"；帮助页长段落另按 ~62em 折行，
   不至于一行 100 多字。

**改完实测**：1920 宽时那 1136px 的空白降到 **135px**；2560 宽时同样 135px
（内容列封顶）。1200 及以下**完全不变**（默认窗口 780×660 本来就是单列最优宽度）。
任何宽度下都没有横向滚动条。
