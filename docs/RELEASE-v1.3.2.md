# Quick Search v1.3.2 发布说明

> 发布日期：2026-10-20
> 上个版本：v1.3.1
> 这一版只修一件事：**快捷键引擎点下去没反应**（章鱼速贴那类）。

---

## 真正的原因：发按键的时候，横条自己还占着前台

你报的：

> 「我点章鱼速贴快捷输入，它还是不能够把那个窗口唤出来。」

前两版我一直以为是"按键注入方式"的问题，改了两轮都没修好。这次从**你的日志**里
直接看到了答案：

```
open_search: 章鱼速贴快捷输入 有可见窗口 → 定向投键（不抢焦点）→ 成功
模拟按键 alt+v -> 已定向投递（前台未变动）
dismiss_bar: 已收起横条（锚点一并清掉）      ← 收起排在发键之后
```

**`dismiss_bar()` 排在发键之后。** 也就是说：

- 你点横条上那颗图标 → **横条自己是当前前台窗口**；
- 就在这一刻注入 `alt+v` → 键打在了**我们自己身上**；
- Octoclip 的 `alt+v` 是系统级全局热键，它要的是"真正注入到系统"的按键，
  而我们自己的窗口把这次输入吃掉了 → 目标程序毫无反应。

对照实验（同一台机器、同一个 Octoclip 进程）：

| 发键时的前台窗口 | Octoclip 能被唤出吗 |
|---|---|
| 你原来在用的窗口（浏览器等） | **能** |
| 横条自己 | **不能** |

### 修法

顺序对调，中间留一拍让前台切换落地：

```
原来：  发按键（横条还在前台）→ 收起横条      ✗ 键打到自己身上
现在：  收起横条 → 等 60ms → 发按键           ✓ 键落到你原来的窗口
```

---

## 顺带删掉一处"自作聪明"的实现

上一版我加过一个用**窗口消息**把按键"直接投给目标窗口"的做法
（想做**不抢焦点**）。它看起来很美，但**根本不能用**：

- `PostMessage` 返回成功只代表"消息塞进了那个窗口的消息队列"，
  **不代表对方会处理它** —— 很多程序压根不读这条消息，进去就沉了；
- 更坑的是它**静默失败**：日志里写着"定向投键成功"，你那边毫无反应。
  我因此白追了两轮才定位到真相。

现在这条代码路径**已删除**，只剩一条：**老老实实注入按键，交给系统分发**。

代码里留了一整段注释记这个教训，防止以后又被接回去。

## 安装

单文件，无需任何运行时，覆盖旧的 `QuickSearch.exe` 即可。
配置与图标都在 `%APPDATA%\QuickSearch`，不会丢。

> ⚠ 换上之后**请从托盘完全退出旧实例再打开**，确保跑的是新版本。
