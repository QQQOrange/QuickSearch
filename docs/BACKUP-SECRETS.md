# 备份、同步与个人密钥

> 适用版本 **v1.5.9** 起。
> 这份文档回答四件事：个人密钥**怎么存、怎么同步、换机怎么恢复、什么时候会冲突或丢**。
> 结论都对着代码，不是照着功能描述写的 —— 每条后面标了落点，便于核对。

---

## 一、什么算「个人密钥」

软件里有 5 组凭据，它们全部**跟整份配置一起**进备份、进云同步：

| 凭据 | 配置字段 | 泄露后能做什么 |
|---|---|---|
| GitHub 个人访问令牌 | `github_token` | 以**你的身份**读私有仓库、改东西 |
| 百度 OCR Key / Secret | `ocr_key` `ocr_secret`（老）+ `ocr_keys` `ocr_secrets`（多引擎） | 烧你的识别额度 |
| 其它在线识别引擎 Key | 同上两个 map | 同上 |
| WebDAV 账号 / 密码 | `webdav_user` `webdav_pass` | 直接进你的网盘 |
| 备份密码 | `backup_password` | 解开你所有加密备份 |

计数的唯一出处是 `config::secret_count()`。它**只数填了值的项**，纯空白不算；
百度那套有「老字段 + 新 map」两种存法，同一份 Key 只算一次 —— 否则数字对不上，
用户反而会怀疑备份漏了东西。

「关于 → 备份」页显示的「当前配置里有 N 项凭据会跟着备份走」就是这个数字。

## 二、存储与加密：四种载体，两把钥匙

### 2.1 四种载体

| 载体 | 文件 | 谁写的 | 加密 |
|---|---|---|---|
| 主配置 | `config.json` | `config::save_to` | **总是加密** |
| 滚动备份 | `config(时间).QuickSearch` | 同上（每次保存留一份，只留最新 1 份） | **总是加密** |
| 云端 / 手动备份 | `config(时间).QuickSearch`（云端按时间戳累积） | `backup_payload` | **总是加密** |
| 快照 | `config.before-webdav(...)` `config.before-restore(...)` | 直接复制主文件 | 跟着主文件（密文） |
| 明文导出 | `config(时间).qsconf` | `export::write_plain` | **默认明文**；含令牌时强制加密 |

> 磁盘上**没有任何明文**。这条从 v1.4.0 起就成立了：`save_to` 里加密失败会
> 直接放弃写盘，而不是"退化成写明文"。

### 2.2 两把钥匙

加密算法是 **AES-256-GCM + Argon2id**（m=19MiB, t=2, p=1）。真正的差别在钥匙：

```json
{ "qsEnc": 1, "kdf": "argon2id", "salt": "...", "nonce": "...", "data": "..." }   ← 备份密码
{ "qsEnc": 2, "alg": "dpapi", "data": "..." }                                    ← Windows 账户
```

| 钥匙 | 什么时候用 | 谁能解开 | 换电脑 |
|---|---|---|---|
| 备份密码（`qsEnc:1`） | 用户设过备份密码 | 任何机器 + 同一个密码 | ✅ 能 |
| Windows 账户（`qsEnc:2`） | **没设**备份密码时兜底 | 只有做它的那台机器 / 那个 Windows 用户 | ❌ 不能 |

选择逻辑只有一行（`crypto::seal`）：密码非空用密码，否则 DPAPI。

**这是最容易误判的一点**：界面上曾经写着「留空 = 不加密」，那句话是错的。
留空**仍然是加密的**，只是换成了"只有本机能解"的钥匙。v1.5.9 起界面上直接显示
结论（`backup_security_state` → `portable`），不再让人靠猜。

### 2.3 备份密码自己存在哪

- 存在 `config.json` 里（`backup_password`），所以它跟着备份走；
- 另存一份到 `backup.key`，用 DPAPI 加密 —— 这样主文件坏掉之后，
  加密备份仍然解得开。

⚠ 诚实说明这里的边界：`backup.key` 和 `config.json` 在同一个私有目录下，
**能读到这两个文件的程序/人，就能拿到备份密码**。它防的是"文件被单个拷走"
和"网盘上那份被看到"，防不住"本机已经有完整读写权限的攻击者"。

## 三、同步机制（WebDAV）

### 3.1 一次同步做什么

`webdav_sync_on_start_inner`，启动后约 6 秒跑一次（配置在 setup 里缓过）：

1. 找出云端**最新的一份**（列目录取 mtime；列不出目录的网盘退回固定文件名 `LEGACY_FILE`）。
2. 拿它的 mtime 和本机 `config.json` 的 mtime 比：

| 情况 | 动作 |
|---|---|
| 云端没有备份 | 本地写一份 + 上传（`backup_once`） |
| 云端比本机新 **超过 2 秒** | 先留本机快照 → 下载 → `restore_from_text`（整份覆盖） |
| 其余（含服务器不给时间） | 本机 → 云端（`backup_once`） |

2 秒是容差，用来吃掉时钟抖动和文件系统时间精度；没有它，两台机器会互相"更新"。

### 3.2 上传有节流

`changed_since_last_backup()`：配置自上次成功备份后一个字都没改，就不再推。
否则每次启动都在云端多一个文件。而成功上传之后才写"已备份"记号 ——
失败必须能被下次重试（`mark_backup_done`）。

### 3.3 一条硬规则

**隔离实例（测试/探针）绝不碰云端。** `is_isolated_instance()` 为真时启动同步直接返回。
理由：这类实例会先拉云端（无害），但退出时会把临时配置推回去（有害）。

### 3.4 并发

所有云操作（上传、恢复、删除、列表）都过 `SyncGuard`，RAII 守卫，panic 也不会把
标志永久留在 `true`。抢不到锁的当场让位（"上一次云操作还没结束"）。

## 四、跨设备恢复流程

### 4.1 前提：这台机器**设过**备份密码

> 这是唯一能跨机的路径。**换电脑之前先确认这一步**。

```text
旧电脑：备份页 → 备份密码填一个 → 立即备份（本地 + 云端）
新电脑：装软件 → 备份页 → 填同一个密码 → 「从云端恢复」选一份
        → 恢复完，令牌 / OCR Key / WebDAV 密码全部就位，不用重填
```

令牌也可以单独走「数据 → 导出」：勾「个人访问令牌」→ 导出时会用备份密码加密
→ 新机器上把密码设成同一个，再「导入配置文件」。

### 4.2 没设密码 = 只有本机能解

DPAPI 信封绑在**做它的那台机器 + 那个 Windows 账户**上。换机器、重装系统、
换 Windows 用户，都解不开。这不是 bug，是"不需要密码就能加密"的必然代价。

看「备份」页那条状态条就知道自己现在在哪一边：

- **✓ 可跨设备恢复** —— 用的是备份密码，放心换机；
- **⚠ 仅本机可解** —— 现在这份换机器就打不开，想跨设备就补个密码再备份一次。

### 4.3 恢复失败时会看到什么

以前只会得到一句「DPAPI 解密失败」，用户不知道是文件坏了还是自己操作错了。
v1.5.9 起按原因分三种说法（`unseal_hint`）：

| 情况 | 提示的是什么 |
|---|---|
| DPAPI 信封解不开 | 这份是做它的那台电脑加密的，换机解不开；以后先设备份密码 |
| 密码信封，但本机没填密码 | 去「备份」页把当时那个密码填上 |
| 密码信封，填了但不对 | 密码不匹配，改成当时那个 |

## 五、冲突处理

同步是**整份覆盖**，没有字段级合并。这是刻意的：字段级合并在两台机器同时改不同
设置时会产生"谁也说不清"的中间状态，而用户对"整份"至少有直觉。

### 5.1 谁能覆盖谁

| 场景 | 结果 |
|---|---|
| 云端 mtime 比本机新 > 2s | 云端覆盖本机（先留本机快照） |
| 否则 | 本机推上去（云端保留历史，不删旧的） |
| 用户手动「从云端恢复」 | 无条件用选中的那份（用户明确指定） |
| 用户手动「载入配置备份」 | 无条件用选中的那份 |

手动恢复是**有意的破坏性操作**，所以恢复前都会留 `config.before-restore(时间)` 快照。

### 5.2 密钥不会被"同步"无声清空

这是本轮补的一条，也是真实会发生的场景：

> A 机填了令牌，B 机没填。B 改了图标、备份上云 → A 机启动同步，
> 按"云端较新"整份拉下来 —— B 那份里 `github_token` 是空串，A 的令牌就没了。
> 之后 A 所有 GitHub 请求变成匿名（每小时 60 次），用户完全不知道原因。

现在的规则（两条路径分别落实）：

| 备份格式 | 保护方式 |
|---|---|
| View（老备份 / 云端 / 手动导出） | `apply_view` 对 `githubToken` **空值不覆盖**（键缺失同理） |
| Config（`save_to` 写出来的滚动备份） | 整份赋值，所以显式调 `keep_local_secret` 保住本机值 |

同时，备份里**真有**令牌时会照常恢复进来（换机不用重填）—— 保护的是"被清空"，
不是"被更新"。

恢复完成后 toast 会补一句，把结果说清楚：

- `；本机的个人访问令牌已保留（备份里没有，没被清掉）`
- `；个人访问令牌已随备份恢复`
- `；个人访问令牌为空（备份里没有），需要的话请重新填`

### 5.3 导入是合并式，不是覆盖式

`.qsconf` 导入只灌文件里勾过的那几组键（`apply_view`），**别的键原样不动** ——
所以"把搜索引擎配置发给同事"不会清掉他的收藏夹。

⚠ 但**同一组里的键**是覆盖的。一份带 `githubToken` 的导入文件会把你的令牌换成
文件里的值。这不是静默的：`import_items` 会比较前后值，变了就在提示里加一句
「个人访问令牌已被文件里的值替换」。用户可能就是想换，所以不阻止，但必须说出来。

### 5.4 已知的边界（不做，但要知道）

- 两台机器**同时**改了不同设置：后同步的那台会覆盖前一台的改动。云端保留历史，
  可以去「从云端恢复」里挑回上一份。
- 没有三方合并，没有冲突文件，没有逐字段 diff。

## 六、安全边界

### 6.1 导出：不勾不加密，勾到隐私项强制加密

`.qsconf` 的设计初衷是"发给同事就能用"，所以默认不加密。页面上有一个
**「加密导出」勾选框**，由用户决定这一份要不要加密。

但有一条例外：**只要选中的数据含隐私内容，就强制加密**，勾选框会被自动勾上
并锁住（`export::needs_encrypt`）。

| 导出内容 | 用户勾选框 | 落盘形态 |
|---|---|---|
| 普通配置（引擎 / 外观 / 图标 / 识图） | 不勾 | 明文 JSON，接收方直接导入 |
| 普通配置 | 勾了 | `qsEnc:1` 信封 |
| **含隐私组且有内容** | 勾没勾都一样 | **强制 `qsEnc:1`**；没设备份密码就**拒绝导出** |

"隐私组"由 `export::GROUPS` 的 `private` 标记决定：`apiKeys`（识别引擎凭据）、
`secrets`（GitHub 令牌）、`favorites`（收藏内容）、`backupSettings`（WebDAV 密码 /
备份密码）。判据是「勾了隐私组 **且** 那个组真的带了非空值」——
勾了令牌组但本机没填令牌，不会逼你去设密码；令牌本身另有一道
`contains_secret` 兜底，看的是**值**而不是组的标记。

拒绝而不是"退回明文"或"用 DPAPI"：前者等于把凭据发出去；后者换机解不开，
等于给用户一个用不了的导出文件。

### 6.1.1 导入加密文件：用户自己输密码

导入分两步（`import_items` → `qs://import-need-password` → `import_with_password`）：

```text
选文件
  ├─ 明文        → 直接导入
  ├─ DPAPI 信封  → 直接导入（钥匙是 Windows 账户，问用户要密码没意义）
  └─ 密码信封    → 弹框输密码 → 输对才导入
```

密码**只用于解这一个文件**：不写进配置、不进日志、关掉就丢。
也**不会**拿它去改「备份」页那个备份密码 —— 那会连累这台机器上所有其他加密备份。

输错密码时输入框**不关**（后端把待导入路径放回 `IMPORT_PENDING`），改一下再试即可，
不用重新选文件。点「取消」会调 `import_cancel` 把待导入的路径丢掉。

### 6.2 日志里没有凭据

- 令牌只记字符数（`config::sanitize` 里的日志），不记值；
- 备份密码同理；
- 探针每次都会断言"日志里搜不到令牌原文 / 备份密码原文"。

### 6.3 恢复别人的备份 = 接受别人的凭据

一份 `.QuickSearch` 或 `.qsconf` 里的凭据是**文件里的值**，不是你的。
恶意文件可以塞一个攻击者的令牌进来 —— 之后你的 GitHub 请求都走他的账号
（他能看到你查了哪些仓库）。缓解措施是提示（见 5.3），不是拦截：
拦截会让"我真的想换令牌"做不到。

**结论：只恢复你自己产生的备份。**

### 6.4 密码丢了就真的没了

没有找回、没有后门、没有客服重置。Argon2id + AES-GCM 的密文，密码不对就是一个
字节都出不来。请在设密码的当天就想清楚记在哪里。

### 6.5 共享机器 / 多 Windows 用户

- DPAPI 信封：**同机器不同 Windows 用户之间解不开**（这是好事）；
- 密码信封：只要知道密码，任何账户都能解 —— 共享机器上请依赖密码本身。

### 6.6 内存里的凭据

Rust 的 `String` 在被释放时不做清零，凭据在进程内存里会短暂残留。
这一轮没有引入 `zeroize` 之类的手段：它挡不住同一用户权限下的内存读取，
收益远小于代价（要改遍所有结构体）。**安全模型是"本机账户可信"**，
在这个模型下这条不构成额外风险。

## 七、一分钟速查

| 我想… | 怎么做 |
|---|---|
| 换电脑且保住所有 Key | **先设备份密码** → 立即备份 → 新机填同密码 → 从云端恢复 |
| 只把令牌带到另一台机器 | 数据页勾「个人访问令牌」→ 导出（**自动强制加密**）→ 新机上「导入配置文件」→ 弹出密码框时输入导出时用的密码 |
| 确认现在这份备份能不能换机用 | 看「备份」页的状态条：✓ 可跨设备 / ⚠ 仅本机 |
| 只把引擎配置发给同事 | 数据页只勾「引擎配置」→ **不勾**「加密导出」→ 得到明文，可直接给 |
| 给同事一份加密的配置 | 勾上「加密导出」→ 告诉他们密码（别和文件走同一条路发送） |
| 令牌在另一台机器上被清空了 | v1.5.9 起不会了；老版本请检查「备份」页的令牌输入框 |
| 想看看额度用掉多少 | 「关于 → 更新」里令牌框下面那行：本小时已请求 X 次 / 共 Y 次 |
| 恢复错了备份 | 备份目录里有 `config.before-restore(时间)`，点它退回去 |
