# Quick Search v1.3.3 发布说明

> 发布日期：2026-10-20
> 上个版本：v1.3.2
> 这一版做一件事：**快捷键引擎不再把后台挂着的应用强行换到前台**，
> 并且把"要不要换出来"做成**每个引擎自己的开关**。

---

## 一、你提的逻辑问题

> 「如果这个软件已经存在于后台，那没有必要说我触发这个快捷键的时候把这个快捷键
>   给换出来。比如说我设置了一个 alt+a 的微信截图快捷键，那微信在后台挂着的时候，
>   那就算它需要检测微信留存，那没有必要把微信的窗口换出来，然后再 alt+a。
>   这是一个逻辑上的问题啊。」

对的，是我上一版的妥协留得太久。v1.3.2 为了修章鱼速贴，我把这段写成了
**"无条件抢焦点"**。而章鱼速贴失败的真实原因是**横条自己占着前台**
（已在 v1.3.2 里通过"先收横条再发键"修掉）—— 病根没了，就不该继续用
"每次都把人家窗口弹出来"这种粗暴手段。

### 现在的行为（默认）

应用**已经在后台跑** → **不动它的窗口**，直接把按键注入给系统。

微信截图、章鱼速贴、各种截图/剪贴板工具都走这条：你正打字、正在别的窗口
操作，点一下横条上的图标就完事，**手上的事一点不被打断**。

> 应用**本来没在跑**时仍然会先把它拉起来（不然按键无处可去），
> 那种情况让它露出来是应该的 —— 用户刚刚"打开"了它。

---

## 二、每个快捷键引擎多了一个开关

> 「在每一个快捷引擎里面添加个按钮，打开这个按钮之后，点击这个快捷引擎图标
>   触发快捷键会把主窗口打开，如果把这个按钮关闭，那么触发快捷引擎功能就不会
>   把相应软件的主窗口打开。」

**位置**：设置 → 引擎库 → 点一个快捷键引擎 → 「绑定应用」那一组里，
「以管理员身份打开」和「启动后再等多久」下面，新增：

```
把应用窗口调到前台再发键            [开关]
```

| 开关 | 行为 | 适合 |
|---|---|---|
| **不勾（默认）** | 应用已在后台 → **不弹它的窗口**，直接发键 | 微信截图、章鱼速贴这类后台常驻 + 全局热键的工具 |
| **勾上** | 每次触发都先把它的**主窗口摆到最前面**再按键 | 必须在那个窗口里才生效的程序（老式 Win32 菜单命令、只吃局部热键的软件） |

**老配置不需要改**：没有这个字段时一律按"不勾"处理 —— 升级后你会立刻得到
想要的行为。

## 三、验证

用真实的两个第三方窗口做对照实验（`qs_audit/bring_front_check.py`）：

| 开关状态 | 触发前前台 | 触发后前台 | 判定 |
|---|---|---|---|
| **关** | `0x1091884`（别的窗口） | `0x27a151a`（**仍不是目标**） | ✅ 没把窗口换出来 |
| **开** | `0xaa16a0`（别的窗口） | `0x19a1346`（**= 目标窗口**） | ✅ 成功换出来 |

日志也能直接看到判断过程：

```
app_bring_front = false →  抢焦点=false（开关键=false 刚拉起=false）
                           模拟按键 alt+z -> 已发送 投向=当前前台

app_bring_front = true  →  抢焦点=true（开关键=true 刚拉起=false）
                           抢到焦点 → 发键
```

其余回归：

| 项目 | 结果 |
|---|---|
| `cargo test --release` | **280 / 280** |
| `cargo clippy --release` | **0 warning** |
| `cargo build --release` | 0 warning |

> 新增了一条守卫测试（`engine_entry透出启动延迟` 里补的断言）：
> `app_bring_front` 必须从配置一路透到运行时视图。**如果这一层没透出，
> 开关就永远读成 false，你勾了也没用** —— 这正是最容易出的错。

## 安装

单文件，无需任何运行时，覆盖旧的 `QuickSearch.exe` 即可。
配置与图标都在 `%APPDATA%\QuickSearch`，不会丢。

> 已在用 v1.3.x 的话：打开软件就会看到更新提示，点一下即可。
