## 1 产品目标

### 1.1 一句话定位

**让"选中一段文字 → 去某个网站/软件处理它"这件事，从"复制、切窗口、开浏览器、粘贴"四步，变成一次点击。**

### 1.2 要解决的三个真实痛点

| # | 痛点 | 现状（无本产品时） | 目标 |
|---|---|---|---|
| P1 | 划词后要搜索，得来回切窗口 | 复制 → Alt+Tab → 浏览器 → Ctrl+L → 粘贴 → 回车 | **选中即弹横条，点一下就走** |
| P2 | 想搜的东西散在几十个站 | 记不住 URL / 每次都要翻书签 | **一个横条装 777 个入口，按别名可搜** |
| P3 | 屏幕上看到的图/字想取出内容 | 手动打字 / 截图后到处传 | **框一下 → 识图或识别文字** |

### 1.3 非目标（明确不做）

- ❌ **不做浏览器**：识图/搜索一律交给系统默认浏览器，不内嵌 WebView 展示网页。
- ❌ **不做账号体系**：没有登录、没有云端同步用户数据（WebDAV 是用户自己的网盘）。
- ❌ **不做截图图床**：绝不替用户把截图上传到第三方（识图仅交给用户勾选的引擎）。
- ❌ **不读取用户输入**：全局钩子只判断"有没有选中"，不会记录敲了什么。

### 1.4 成功指标

| 指标 | 目标 | 当前实测 |
|---|---|---|
| 松手 → 横条可见 | < 150 ms | 端到端日志可测 |
| 松手 → 识图截图完成 | < 100 ms | **52 ms** |
| 冷启动到托盘就绪 | < 3 s | — |
| 单元测试 | 全绿 | **250 / 250** |
| 静态检查 | 零告警 | **clippy 0** |
| 装机内存（无设置页） | < 450 MB | 410 MB |

## 2 用户与场景

### 2.1 目标用户

- **高频信息检索者**：写材料、查资料，一天几十次"划词去搜"。
- **需要多源对照的人**：同一个词要在百度/必应/Google/知乎分别看一遍。
- **屏幕取字/取图的人**：从 PDF、图片、视频、报错弹窗里捞文字。

### 2.2 核心场景

| 场景 | 触发 | 结果 |
|---|---|---|
| S1 划词搜索 | 选中文字松手 | 横条弹出 → 点引擎 → 浏览器打开搜索页 |
| S2 复制即搜 | Ctrl+C | 同上（可选开关） |
| S3 截图识图 | 横条点「识图」→ 框选 | 各引擎标签页打开，AI 家自动粘贴 |
| S4 屏幕取字 | Ctrl+Alt+O 或横条点「OCR」→ 框选 | 结果窗显示文字，可复制/整理 |
| S5 启动软件 | 横条点自定义软件图标 | 拉起该软件（可选先确保在跑） |
| S6 发快捷键 | 横条点快捷键引擎 | 把组合键发给前台软件 |
| S7 收藏 | 横条点 ★ | 存进两级目录，可拖拽整理 |

## 3 页面结构

### 3.1 窗口清单

| 窗口 | label | 生命周期 | 说明 |
|---|---|---|---|
| 横条 | `bar` | 常驻（隐藏） | 主交互面。平时不可见，触发时出现在光标/选区旁 |
| 设置 | `settings` | 按需，**关闭 3 分钟后销毁** | 10 个分页 |
| OCR 结果 | `ocr` | 按需 | 显示识别文字，多引擎时并排多框 |
| 图标编辑器 | `iconedit` | 按需 | 编辑前后对比 + AI 自动抠图 + 涂抹修饰 + 换模型 + 导出 |
| 框选遮罩 | `region` | 按需（用后即毁） | 全屏十字准星，框选区域 |
| 程序点选器 | `picker` | 按需 | 十字准星点一下选程序 |

### 3.2 横条结构

```
┌──────────────────────────────────────────────────────────┐
│ [引擎1] [引擎2] [引擎3] │ [OCR] [识图] [★] [⋯ 更多引擎]  │
└──────────────────────────────────────────────────────────┘
        ↑ 拖拽可换位 / 右键菜单 / 分隔线可插入
```

- **引擎区**：`bar_list` 有序列表，可拖拽排序；含 `@ocr` / `@img` 哨兵。
- **功能按钮**：OCR、识图、收藏夹、更多引擎（固定位）。
- **展开态**：点「更多引擎」向上弹出面板（引擎库 + 最近使用 + 收藏夹）。

### 3.3 设置页分页（10 个）

| 分页 | 内容 |
|---|---|
| 通用 | 触发方式、横条外观、图标大小、主题、延时、程序过滤 |
| 引擎 | 横条成员排序、全部引擎（四级目录 + A–Z 索引）、自定义引擎 |
| AI 工具 | AI 引擎提问后缀 |
| 文字识别 | 总开关、本地环境检测、引擎列表（15 家）、凭据、同时识别 |
| 识图搜索 | 总开关、引擎勾选（12 家）、AI 按键延迟、AI 优先、公网地址 |
| 收藏夹 | 两级目录管理 |
| 数据 | 明文导出 / 导入 |
| 备份 | 本地加密备份、WebDAV 云端同步 |
| 帮助 | ① 触发 ② 横条 ③ 引擎 ④ 识图 ⑤ 文字识别 |
| 关于 | 版本、构建时间、开发者 |

### 3.4 结果窗（OCR）

- **单引擎**：一个 `#text` 文本框。
- **多引擎（同时识别）**：`#panesMulti` 下**每家一个文本框并排**，各带引擎名标题。
- 底部段控：每家一颗胶囊 + 「都看」。
- 工具行：复制、打开链接、文本整理（去乱码 / 全角半角 / 合并换行 / 去空格）。

## 4 功能边界

### 4.1 触发与横条

| 功能 | 边界与规则 |
|---|---|
| 划词触发 | 鼠标松开时若检测到选中文本则弹；可设延时（`delay_ms`，默认 0） |
| 复制触发 | 全局钩子捕获 Ctrl+C，读剪贴板取词 |
| 程序过滤 | `filter_mode` = off / blacklist / whitelist，按进程名匹配 |
| 横条定位 | 优先贴光标下方；放不下则上移；不出工作区 |
| 暂停 | 托盘菜单可暂停，暂停时所有触发失效 |

**已知限制**：
- 部分游戏全屏独占时钩子可能失效。
- UIA 读不到选区的程序会退到「模拟 Ctrl+C + 读剪贴板」，该程序若禁用复制则无文本。

### 4.2 引擎

| 类型 | 行为 | 边界 |
|---|---|---|
| `search` | 拿选中词填 `%s` 打开 | URL 必须含 `%s`；否则拒绝保存 |
| `open` | 原样打开页面 | URL **不能**含 `%s` |
| `hotkey` | 把组合键发给前台软件 | 必须能解析；可选绑定应用 |
| 软件直达 | 按开始菜单名 / 协议拉起 | 仅内置「常用软件」条目 |

**数量上限**：自定义引擎最多 60 个；识图同时最多 15 个标签页。

**别名搜索**：搜索框比对 `name + alias`，777 个引擎中 **85%** 带别名。

### 4.3 识图

| 模式 | 引擎 | 行为 |
|---|---|---|
| `Upload` | 百度 / Yandex / SauceNAO / trace.moe | 自己 POST 上传，拿结果 URL 开页 |
| `Page` | 6 家 AI（豆包/通义/Kimi/智谱/元宝/文心） | 打开页面 + 自动 Ctrl+V / Enter |
| `Url` | Yandex / trace.moe 的地址版 | 需用户填公网图片地址，否则跳过 |

**关键规则**：
- **AI 优先**（默认开）：AI 那一段先开、按完键，再开其余引擎。
- **多家 AI 才关按键**（默认开）：勾 ≥2 家 AI 时自动不发键（一次只能喂一个输入框）。
- **AI 按键延迟可配**：开页→Ctrl+V 默认 1200ms，Ctrl+V→Enter 默认 900ms。
- 截图**不落盘**（仅内存）；剪贴板用后还原（可选保留）。

### 4.4 文字识别

- **默认引擎**：跑哪几家由「默认引擎 + 同时识别名单」派生。
- **凭据**：由引擎注册表决定要填几项（Key / Secret / 模型名 / base_url）。
- **模型列表**：默认只留**视觉模型**（纯文本模型吃不了图）。
- **多引擎结果**：并排多文本框。
- **脱困**：默认引擎缺凭据但本机有本地 OCR 时，**这一轮临时用本地**（不改用户配置）。

### 4.5 图标编辑器

- 支持 png/jpg/ico/webp/gif/bmp/svg。
- 支持 png/jpg/ico/webp/gif/bmp/svg（SVG 是矢量图，没有位图背景可消，但可原样应用）。
- **AI 自动抠图（r80 起）**：用神经网络（U²-Net / RMBG）出 alpha，本地算法只做边缘去色。
  - **模型可选、按需下载**（4.4MB ~ 168MB 四档，见下节）；默认推荐 **u2netp（4.4MB）**，
    实测 10 个真实图标里抠对 7~8 个、平均 63ms —— 它比 168MB 的 RMBG 更准，
    因为 RMBG-1.4 是在人像/商品上训练的，会把图标里的文字和底座删掉。
  - 开关键语义（r80b）：**默认关**。关着时点「换图标」直接替换文件、
    界面上**没有**「编辑图标」按钮；打开后才会进编辑器。
  - 缺模型/运行库时给**能操作**的中文提示（告诉你去哪点下载），不静默失败。
- **涂抹修饰（r80g）**：抠完可直接在**结果图**上涂，所见即所得。
  - 两支笔：**擦除**（修瑕疵主力）、**保留**（AI 误删主体时救回来）。
  - **放大 1~8×** 再涂（小瑕疵不放大必然涂错）；整笔撤销、重来（回到 AI 刚抠完的样子）、应用涂抹。
  - 前端合成，不发回后端 —— 用户要的是"涂完立刻看到变化"，而不是"涂完再点一次抠图"。
- **换模型重抠（r80g）**：编辑器里可临时换模型重新抠（只列已下载的）。
  一次性选择，**不改**设置里的默认模型。
- **导出（r80）**：抠好的结果可另存到任意位置（恒存 PNG，因为要保透明）。
- **光学尺寸归一**：带透明留白的图标自动放大到视觉等大。
- 上限 512px（超出先缩放）。
- 已知边界：AI 对**扁平图标的内部封闭区域**判断不稳（会把主体内部当背景）——
  这正是"涂抹修饰"存在的理由；也可以调「前景确信度」或换模型。

### 4.6 备份

| 方式 | 加密 | 说明 |
|---|---|---|
| 本地备份 | 可选 AES-256-GCM | `backup_name()` 生成时间戳文件名 |
| 明文导出 | 否 | 给别人直接导入 |
| WebDAV | 跟随备份密码 | 自动 MKCOL 建目录，失败重试一次 |

**备份内容**：全部配置（含收藏夹 dataURL、自定义引擎、图标覆盖）；**不含**截图。

## 6 技术约束与设计取舍

| 约束 | 原因 |
|---|---|
| 同步 HTTP（ureq），不用 tokio | 丢后台线程即可，省一整个异步运行时 |
| 命令必须脱开调用栈再建窗口 | 否则主线程建 WebView2 会死锁 |
| 所有窗口共用一套 WebView2 参数 | 否则环境冲突、窗口建不起来 |
| 配置原子写（tmp + rename） | 崩溃时正式文件永远完整 |
| 默认以管理员运行 | 否则 Ctrl+C 送不进同为管理员的程序 |
| 框选遮罩四层兜底 | 它铺满全屏，留着等于锁死鼠标 |
