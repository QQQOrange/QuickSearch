# v1.5.15 —— 缺运行组件时，不再"双击没反应"

这一版只改了一件事，但它决定了很多人在某些电脑上**第一次打开这个软件时能不能用**。

---

## 要解决的问题：缺 WebView2 时，程序一声不响地消失

Win11 自带 WebView2；Win10 上它通常跟着 Edge 一起装好了。但在
**LTSC、精简版、部分企业镜像**里，它是被移除的 —— 这时候双击图标：

| | 以前 | 现在 |
|---|---|---|
| 现象 | 什么都不发生，或者闪一下就没了 | 弹一个说明框，告诉你缺什么 |
| 日志 | 只有一行 `failed to create webview` | 明确写"未检测到运行时" |
| 出路 | 用户自己猜、自己搜 | 点「是」直接去微软官方下载 |

原因是 Tauri 的所有窗口都靠 WebView2 渲染，建不出来就走 panic 路径退出。
用户既看不到窗口，也拿不到任何解释。

### 检测怎么做

**三层证据，任何一层查到就算已安装**：

1. WebView2 自己的接口 `GetAvailableCoreWebView2BrowserVersionString`
   —— 程序真正要用的就是它认的那个运行时，也覆盖 fixed-version 与用户级安装；
2. 注册表 `EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv`
   （系统级 WOW6432Node / 原生视图 + 用户级，各查一遍）；
3. 磁盘上的 `msedgewebview2.exe`（三处标准安装目录，兜"注册表被清理过"）。

这个方向是**刻意**的：误判成"没装"会把一台本来能用的电脑挡在门外（用户还以为
软件坏了），比漏判严重得多。所以只有三层**全都**查不到时才认定缺失。

### 给了两条逃生口

```text
QuickSearch.exe --skip-webview2-check      # 不做检查，强行启动
QuickSearch.exe --simulate-no-webview2     # 反方向：假装没装，用来演示这个提示框
```

第二条是为了让这条路径**可验证** —— 不然它只在坏机器上出现，谁也看不见。

## 顺带修掉一个真实隐患

配置里开着「开机自启」时，把 exe 复制一份到别处试跑（配置一起拷过去），
一启动就会把 `HKCU\...\Run` 里的路径改成**那个副本** —— 正式版的开机自启
被悄悄顶掉，下次开机起来的是那份副本。

现在带 `QS_SKIP_AUTOSTART=1` 就不碰自启项（便携副本 / 测试副本用）。

## 更新包校验

SHA256: D6047F87EF5755DD60536320DCFF7F78D589897514BAC3E1AE8A19AEB6DBF5C5

| 文件 | 大小 | 校验值 |
|---|---|---|
| `QuickSearch.exe` | 13,657,088 字节 | 同上 |

> 上面那一行 `SHA256: <64 位十六进制>` 是**自动更新用的**：程序会从发布说明里
> 解析它，校验用户下到的更新包是不是我们发的这一份（`update::sha_from_notes`）。
> 删掉它会静默退化成"只比体积"。

## 装机

覆盖 `QuickSearch.exe` 即可，配置、收藏夹、图标都不动。

> 这一版没有改任何配置结构，也没有迁移 —— 从任何旧版本直升都不需要额外操作。

## 已知限制

- **真"缺 WebView2"的机器没有实测**。本机是装了 155 的，验证用的是
  `--simulate-no-webview2` 模拟。第一次在真坏的机器上跑才算端到端闭环。
- 提示框是 Win32 原生 `MessageBox`（那时候还没有 WebView2，做不出带链接的界面），
  所以没法放可点击的网址 —— 点「是」就是那个"可点击的下载入口"。
