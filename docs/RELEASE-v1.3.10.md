> 发布日期：2026-10-22

## ① 前两次为什么都没修好

| 版本 | 当时的判断 | 实际 |
|---|---|---|
| v1.3.8 | OCR 只是把网址**断开**（`https:// www.baidu.com`），放宽判据接回去就行 | OCR 会**认错字母**，判据救不回来 |
| v1.3.9 | 认错字没法救 → 后台模拟一次 Ctrl+C 读**原文**替换掉 | 触发条件写窄了：只在"一条链接都没认出来"时才复核 |

用户的日志给了两个反例，都落在 v1.3.9 的盲区里：

```text
# 反例一：认错字（连一次都没认出链接 → v1.3.9 能救）
nttos.'//altnuo.corrvxanaenranaos/twlnl<le-tray

# 反例二：塞空格（认出来了，但是**截断**的 → v1.3.9 放过了）
https://www.douyin.com/jingxuan?modal id=76946313 546769009
                                   ↑ 这里被塞了空格，extract_links 只截到 ...?modal
```

反例二比"按钮不亮"更坑：按钮是亮的，点下去打开的是半截地址。

## ② 这一版怎么修

`exact_reread_why` 的判据改成按「**认出来的链接占整段多少**」来判：

| 情形 | 处理 |
|---|---|
| 认出来的链接覆盖整段 ≥90% | **不复核**（OCR 认得准，不为正确的事付无谓代价） |
| 认出 ≥2 条链接 | **不复核**（都认出来了，按钮本来就把它们分别开标签页） |
| 抹掉空白后整段就是一条网址，但认出来那条没覆盖它 | **复核** ← 反例二 |
| 有网址/路径的影子却一条都没认出来 | **复核** ← 反例一 |
| 浏览器里划了一大段却几乎没认出字（`}`、`00S`、空串） | **复核** |
| 其余（中文、英文句子、代码片段） | **不复核**，剪贴板一个字节都不碰 |

复核走的是 Ctrl+C「迟到补」那条现成通道（`push_late_text` → 前端 `qs://text`），
所以文字、`isUrl`、`urls` 一起重算，按钮跟着亮起来，顺带把横条上那份 OCR 错字
换成真正的原文。

## ③ 顺带修掉的配置丢失 bug（真实事故）

**现象**：跑完 `cargo test`，用户真实的 `config.json` 变成了一份 `delay_ms = 4321`
的测试配置 —— 自定义引擎、5 个收藏、自定义图标、OCR/WebDAV 密钥全没了；
更糟的是 `backup_password` 跟着变成空串，启动时 `stash_backup_password("")`
把 `backup.key`（解开加密备份的**唯一**钥匙）删掉了。

**根因**（`config.rs`，两处，都是真 bug 不只是测试问题）：

1. `load_from(path)` 里"启动归一有修改 → 写回磁盘"那一行写的是 `save(&raw)`，
   而 `save()` 写的是**全局** `config_path()`。`load_from` 是可注入版本，测试传的是
   临时文件 —— 于是测试的归一结果被写进了真实数据目录。
   → 改成 `save_to(path, &raw)`，写回自己那个 path。
2. `save_to` 的滚动备份落点用 `backup_dir_of(cfg)`，用户没设备份目录时它恒等于
   `data_dir()`（真实 `%APPDATA%`）。于是**每跑一次测试就往真实目录里塞一份
   "测试配置"的滚动备份**，还按轮转规则删旧的。
   → 改成"没设备份目录时落在**主文件旁边**"（生产环境 path 恒在数据目录，行为不变）。

两条都加了回归测试（`load_from_never_writes_the_global_config_path`）。

**这次的数据是怎么救回来的**：数据目录里躺着 `config.before-webdav(2026-10-22 09-45-48)`
—— 它是 WebDAV 同步前的**明文**快照（10356 字节，完整配置），直接写回 `config.json`，
再用里面的 `backup_password` 重建 `backup.key`（96 字节，和原文件同尺寸）。
之所以能救，是因为 `save_to` 的轮转有"**完整度更高的旧备份一律不删**"这条保护
（r92 加的），那份好备份没被默认配置挤掉。

## ⑤ 已知边界

- 中文句子里夹一个被认错的网址（`详情见hnps//a.com`）仍不触发复核 ——
  判据要求"整段像网址/路径"，放宽到"含 CJK 也算"会让几乎每次中文划词都动剪贴板。
- 目标程序过滤合成按键（微信 4.x 这类）时复核也会失败，横条保持 OCR 那份，
  和以前一致。
- 按钮是**稍后**亮起来的（复核要几十~几百毫秒），不是弹条那一刻就在。
