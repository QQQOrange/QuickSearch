# Quick Search v1.3.5 发布说明

> 发布日期：2026-10-21
> 上个版本：v1.3.4
> 这一版修的是**数据安全**：上一版让用户的全部设置丢了。已完整恢复，并堵死了整条事故链。

---

## 出了什么事（我如实说明）

你更新到 v1.3.4 之后：

- OCR 的 Key / Secret 没了
- WebDAV 的账号密码没了
- 收藏夹的 5 组内容没了
- 两个自定义快捷键引擎（微信截图 / 章鱼速贴）没了
- AI 抠图模型明明在硬盘上，界面显示"未下载"
- 其它设置全部回到默认

**根因不是"更新会覆盖配置"，而是"配置损坏后的自动恢复链断在半路"。**

### 完整的事故链（四个环节，缺一不可）

1. `config.json` 某次损坏（尾部截断之类）；
2. 程序去找滚动备份恢复，但**只会按明文解析** ——
   而你设了备份密码，滚动备份里是**密文信封**（`{"qsEnc":1,...}`），
   于是所有备份"都读不出来"；
3. 退而用默认配置启动，随即 `save` 把默认配置写回；
4. **`save_to` 每次都会删掉其它所有滚动备份** ——
   包括那份"内容完好、只是解不开"的加密备份。
   退路被自己销毁了。

于是：设置全丢，而且**再也捞不回来**。

---

## 修了什么（四道防线，每一道都能单独拦住这次事故）

### ① 加密备份现在能被解开了

`read_backup_config` 原来**先试明文解析**。这是致命的：
`Config` 结构体整个带 `#[serde(default)]`，所以一份密文信封
`{"qsEnc":1,"data":"...","kdf":...}` 会被 serde **"解析成功"** ——
未知字段被忽略、其余全取默认值。于是一份完好的加密备份被当成
"解析成功但内容是空的"。

**现在：先判它是不是密文信封，是就只走解密这条路。**

### ② 备份密码独立存档（`backup.key`）

密码原本**只存在 config.json 里**。主文件一坏、密码字段跟着没了，
加密备份就永远解不开 —— **保护数据的机制反而让数据不可恢复**。

现在把密码另存一份到 `%APPDATA%\QuickSearch\backup.key`。
它和 config.json 同目录、同样受文件系统权限保护，安全性没有降低
（能读 `%APPDATA%` 的程序本来就能读 config.json 里的密码），
换来的是**可恢复性**。

### ③ 恢复时"挑最完整的那份"，不是"取最新的"

`load_backup_of` 原来是"按文件名排序取第一个能读的"。而最新那份
`config.auto(...)` 可能恰好是**配置被清空之后**写下的默认配置 ——
"恢复"恢复出一份空配置，看起来成功了，实际什么都没救回来。

新增 `backup_quality()` 打分：自定义引擎 +40、OCR key +20、
WebDAV +20、收藏 +25、AI 模型 +10……**取分数最高的那份**，
同分才比时间。

### ④ 备份轮转不再"只留一份"

`save_to` 原来每次保存都删掉其它所有滚动备份。
现在：最多留 8 份，且**绝不删除"比本次更有价值"的备份** ——
一份含自定义引擎/OCR/收藏的备份，不能被一份"默认配置"挤掉。

这一条是关键：**恢复失败后用默认配置启动时，那份好备份必须活着。**

### ⑤ 本地滚动备份也加密了

你指出的：「我备份的文件都是加密了，怎么能有没有加密的呢？」

原来的设计是分裂的：
- 云端备份 → 加密 ✅
- 手动导出 → 加密 ✅
- **本地滚动备份 → 明文** ❌

而滚动备份里装着 OCR Key、WebDAV 密码、收藏内容 —— 和云端那份
一模一样敏感。现在设了备份密码就加密。

## 顺手修的两个 UI bug（你报的）

### 更多引擎页面闪烁

`renderPanel` 原来无条件 `panelBody.textContent = ''` 然后重建几百个格子。
而 `qs://config` 广播（改任何设置、拖收藏面板尺寸都会触发）都会走到这里，
用户翻着列表时面板每隔几百毫秒重建一次 —— 视觉上就是闪。

现在加了指纹缓存：渲染输入没变就不重建（和设置页 `renderAllList` 同一套思路）。

### OCR 按 Esc 退不出

`ocr.html` 里的条件是 `document.activeElement !== $('text')` ——
焦点在**结果文本框**里时整条 Esc 被忽略。而点开 OCR 后焦点通常就在那个
文本框里（它自动聚焦方便改字），于是 Esc 完全没反应。

现在：文本框里按 Esc 也关窗口；只有"文本框里有选中内容"时，
第一次 Esc 只取消选中。
