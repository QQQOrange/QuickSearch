# Quick Search v1.5.22

## 修复：明明选中了文字，横条也不弹

### 现象
打开「划选没取到文字就不弹」之后，**确实选中了文字**（OCR 也认出来了），横条仍然不弹。

### 根因（两处叠加）

1. **取词期间被"自己人"判定成用户取消**
   取词完成前会检查 `DISMISS_EPOCH`（"用户收过一次条"的计数），变了就作废这次划选。
   但这个计数**程序性收起也会加**：`capture_by_ocr` 发现横条挡住截图时会自己调一次
   `dismiss_bar()`，于是取词还没结束，epoch 就被改了 —— 日志里的
   `OCR 通道拿到 163 chars` 紧接 `取词期间用户收了条/点了别处 —— 这一次不弹` 就是它。

2. **远程 OCR 超时给得太长**
   划选取词调用远程引擎时超时是 **20 秒**，而"上一次取词未结束"的等待只有 **4.5 秒**。
   远程一慢，后面的连续划选全部被 `上一次取词超过 4.5s 仍未结束，本次放弃` 挡掉。

### 修复
- 新增 `INPUT_EPOCH`：只有**鼠标再次松开**或**按 Esc** 才 +1；取词是否作废改看它。
  程序性收起、自动收起不再误伤。
- 划选取词的远程 OCR 超时 **20s → 4s**（小于 4.5s 的等待窗口，不再堵住下一次划选）。

## 修复后的表现

- 选中文字 → 取词 → **一定弹**（只要取到了非空文字）。
- 取词期间你又**点了一下别处**或**按了 Esc** → 这一次作废，不弹（尊重"我已经走了"）。
- 连续快速划选：上一次取词最多占用 4 秒，不会再让后面几段全被放弃。
- 「划选没取到文字就不弹」仍然只拦"真的没取到文字"的情况（拖窗口 / 拖滚动条等误触）。
