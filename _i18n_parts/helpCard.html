Help From “how do I call it up” to “where does my data live”, in one go

The items below follow the order you'll actually use them in: the first three are enough to get going, the rest are reference details. Every block folds away when you click its title — collapse them all and treat this page as a table of contents.
① How to call it up

Two ways, both of them working in any app:

  • Drag-select some text with the mouse and let go — the bar pops up right where the selection is (this is the main path). Apps differ wildly in how quickly they commit a selection, so internally it waits a moment for the selection to land and retries the copy twice if it fails; that keeps fast swipes and large document windows reliable;
  • Select text with the keyboard and press Ctrl+C — the bar appears just the same (the go-to whenever the mouse is awkward).

How long it waits after you let go is set by “General → Trigger → Show delay”; 100–200 ms avoids the “it pops up while I'm still dragging” feeling.

If it gets in the way in some apps (games, remote desktop, an editor while you take notes), add them to the blocklist under “General → Scope”; if you only want it in a handful of apps, switch that to allowlist mode instead.

② The bar: what it looks like, and why it is that color

The bar is a row of icon tiles, and left to right is the engine order you arranged. Clicking a tile = searching / jumping to that engine with the text you currently have selected.

  • Color: the backdrop follows “Appearance theme” — “Follow system” tracks Windows light / dark mode, and you can also pin it to light or dark;
  • Style (pick one): switch under “General → Bar style”; the page only shows the options belonging to the current style — Default = a solid plate; Frosted = blurs the screen behind the bar; Liquid glass = grabs a patch of the desktop behind it as a texture and does real refraction / chromatic aberration / rim light, and with video playing behind you can turn on “live refraction” so it follows along. Liquid glass needs WebGL2; on a GPU that can't do it the bar drops back to frosted automatically, nothing to manage by hand;
  • Glass preset: once liquid glass is selected, two one-click presets (“Light” / “Standard”) appear at the top; touch any slider below and it becomes “Custom” — a preset is just a shortcut and never fights your manual tuning;
  • Position: by default it pops up hugging the selected text (flipping above when there is no room below); turn on “Anchor the bar to the pointer” and it always follows the mouse.
  • Size: icon size, padding, opacity and frost strength are all adjustable — change them under “General → Preview” and the real thing updates immediately.
  • Move the pointer to a tile's edge, or hold Space and drag, to move the bar; press Esc to put it away.
③ Engines: what ships by default, and how to make it yours

Over seven hundred common sites are built in, all under “Engines → All engines” — one click adds one to the bar. The order on the bar is the order of the search row; drag to reorder on the “Engines” page.

  • Three groups: engines are split into Web engines (search engines / direct URLs), App engines (app search / app launch) and Hotkey engines; the bar's “More engines” panel uses the same structure, so clicking down through it never gets lost even with 700+ entries;
  • App launch = start the local app first: entries in the “Common apps” category (WeChat / QQ / DingTalk / Feishu / WeCom / Tencent Meeting / Zoom / Teams / Epic Games Store …) launch whichever of those is installed on your machine when clicked, and protocols that carry a page even open that page inside the app (DingTalk, for instance, opens its official site inside the client). It tries the app's own protocol first, then the shortcut in the Start menu, and only falls back to opening the web page when neither is installed — machines that have been around a while behave exactly as before;
  • Search right inside the panel: type in the search box of the “More engines” panel and each of the five sub-categories lists its hits; typing at any level searches the whole table (press win+shift+s to look up hotkey engines by their key);
  • Add an engine (three ways): on “Engines → Add engine” click “+ Add engine”, then pick Web engine (an address containing %s searches, one without it opens directly), App engine (an address that launches a local / third-party app), or Hotkey engine (sends a key combo to the foreground app) — the form starts collapsed and only opens once you've picked a type;
  • Separator: for grouping icons; add as many as you like — leading, trailing and consecutive duplicates are cleaned up automatically;
  • Change icon: right-click that row on the bar → Change icon, then pick a PNG from your computer; the image stays on this machine only (moving computers means moving your backup with it);
  • Custom engine: for an intranet search or some niche site, paste an address containing %s and it's in; pick the “AI tools” category and the prompt suffix is filled in for you;
  • Hotkey engine keys: how combos are recorded and which keys are refused — see ⑦ Hotkeys at a glance; how to change the prompt suffix of an AI engine — see ④ AI tools.
  • Hotkey engines can “bind an app” (the light panel when adding / editing a hotkey engine): tick “Make sure this app is running”, click “Choose…” and pick a program (.exe / shortcut); from then on, clicking that tile first checks whether that program is running — if it is, the combo goes straight to it; if not, it launches it, waits for the window and then sends the keys. You can also tick “Open as administrator” (it only affects the launch we perform, and raises a UAC prompt; if the program is already running its privileges are left alone). Leaving this switch off is the old behavior: send the keys to whatever is in the foreground, running or not;
  • Search URLs are editable: if an official page changes its parameters one day, you don't have to wait for a new release — edit the one line yourself.
  • The “Recently used” row: the very top of the bar's “More engines” panel (above all categories) gains this row, listing the engines you just used in most-recent order — the usual few without digging through categories. How many fit in the row is chosen on “Engines → More engines panel”: 5 / 10 / 15 / 20. On a fresh install where nothing has been used yet the row takes no space (better hidden than empty); engines already pinned to the bar never show up here — they are in plain sight already, and copying them would only squeeze out the ones that genuinely need fishing back. Engines that no longer exist in the list are skipped (no dead tile that does nothing when clicked), but your usage history itself is never deleted — if that engine ever comes back, it's still there.
④ AI tools: pick one, click once, the question is already complete

Hand an AI a bare paragraph and it tends to ask “what would you like me to do with this?”. On “AI tools” give each AI a suffix (for example “What does this sentence mean?”); clicking its icon appends that suffix to the selected text before sending it along.

  • An AI without a suffix of its own uses the “Default suffix” above;
  • Some AI sites ignore URL parameters? Turn on “Also copy the prompt to the clipboard”, switch over, click the input box and press Ctrl+V to fill it in;
  • Select the sentence I'm typing right now → click the DeepSeek icon → a complete prompt in a new tab.
⑤ Text recognition (OCR): lift text off the screen as copyable text

Press Ctrl+Alt+O (or the OCR tile on the bar) → the screen dims, drag a box around an area → release and it's recognized. The result window shows the image on top and the text below; when the text contains a link an “Open link” appears. To switch engines, click one in the engine list on the “Text recognition” page (that one becomes the default engine).

Dragging a box around an image rather than around text you want to read? That's a different feature — see ⑤b Image search.

  • Windows built-in (default): uses the OCR that ships with the system — offline, free, fastest, and it needs no account. Environment checks are manual — to find out whether this machine can use it, click “Check local OCR environment” on the “Text recognition” page; if you never click, nothing is checked and no verdict is volunteered;
  • A dozen-plus online engines, and clicking one in the list makes it the default: the chosen one expands (credentials / test connection / model picker all live inside that block), the rest fold down to a single name each; the bar button / hotkey / selection fallback all follow the default engine — there is no such thing as “added but never used”. Two families:
    · LLM-based (SiliconFlow, Kimi, Zhipu, Alibaba Cloud Bailian, Volcano Ark, OpenAI, Gemini, OpenRouter, custom): OpenAI-compatible APIs — fill in the Key, click “Fetch models” and pick a model (vision-capable ones first, and you can type a name by hand);
    · Dedicated APIs (Baidu Cloud, Tencent Cloud, Youdao, OCR.space, Mistral OCR): fill in Key / Secret / endpoint as prompted;
  • Test connection: click it once the credentials are filled in and it really sends a request. Connected, invalid key, no balance, misspelled model name — these are told apart, and the error carries the other side's actual words instead of just a 403;
  • One-click diagnose (every provider has it): measures the time of each step / sends one real request and lays the other side's actual words next to a plain-language suggestion; what each step's button does next is up to you, and it never changes your configuration on its own;
  • Pin the result window to the default engine (on by default): when recognizing on several engines at once, the result window always stays on the default engine's tab — showing its waiting text until it returns, then filling in right there, and it never jumps to whichever one answered first; click the pill at the bottom to look at another. Turning the switch off is “whoever produces text first gets shown”;
  • Recognize several at once (multi-select): inside the expanded default engine, tick the others you want to run too; one recognition then runs them simultaneously on the same image, each with its own section and its own label; the “Show” segment control at the bottom shows one or all (switching does not re-recognize). Anything unticked takes no part and never shows up in the result window — local recognition included.
⑤b Image search: box an area of the screen and let a search engine look at it

It is “one image, two readings” alongside OCR: OCR reads the text on it, image search takes it as an image and searches with it. Click the 🖼 on the bar (or use the hotkey if you set one) → the screen dims, drag a box around an area → on release the browser opens as configured.

  • Twelve engines, one row each: on the “Image search” page every engine gets a row of its own — the checkbox at the start means it takes part, and the three small buttons at the end (default / change icon / question mark) only affect that row. No more “a dozen crammed into one pill”;
  • Default engine: click “Set as default” at the end of a row and it becomes the one (it then reads “Current default” and won't fire a second time). With a default set, a box selection goes straight to the browser without asking which engine to use; with none set, everything ticked opens;
  • Every engine's icon can be changed on its own: the “Change icon” at the end of a row picks a PNG from your computer and affects only that engine (untouched ones keep the default icon);
  • The question mark ❓ at the end of a row: opens that engine's official page / how-to directly. All twelve have their own address, each on its own row;
  • Multi-select search: tick several and one box selection opens a new tab for each engine's results (15 at most; beyond that only the first 15 open);
  • Three modes, and the small print on each row tells you which one it is:
    · Real upload (Yandex / Baidu / SauceNAO / trace.moe): the app POSTs the image itself, gets the result page URL and then opens the browser — your box selection lands on the results, nothing left to do. The defaults are the two that passed hands-on testing in this mode (Yandex + SauceNAO);
    · Open the page (Doubao / Tongyi / Kimi / Zhipu / Yuanbao / Ernie): opens that engine's page with the screenshot placed on the clipboard; these six also send Ctrl+V for you (since r66 a further Enter follows, so the image goes out and it answers directly);
    · By image URL (the URL variant of Yandex / trace.moe): only accepts a public image link you fill in yourself. The app deliberately does not upload your screenshot to some third-party image host and then search by that URL — that would amount to silently agreeing to “hand my screenshot to an image host” on top of agreeing to “search this image”.
  • Use trace.moe for anime screenshots: that row returns data rather than a web page, so the app renders it into a local result page and opens that — title (Chinese included), episode, timestamp, similarity and a preview video are all on it. The page lives in a temp directory and expires once closed;
  • Which ones ask you to “pick a file” (the six AI engines): browsers do not allow pasting into a file input, so a clipboard alone gets you nowhere. These engines therefore leave a temp image for you; click “Choose file” on the page and pick it (the AI input boxes also accept dropping the image straight in). That temp image is overwritten every round and deleted on exit, so at most one exists on disk at any moment;
  • A real upload can still fail: Baidu image search has tightened its anti-bot measures, so an upload may be refused — when that happens the app falls back to opening its upload page, and you click “Upload from computer” and pick that temp image; the flow never dead-ends;
  • Whether it appears on the bar: the “Add to selection bar” switch on the “Image search” page controls that 🖼. Turn it off and image search still works, it just has to be started from the settings page;
  • The 🖼 only shows on the bar when the feature itself is on and “Add to selection bar” is on, following the configuration just like the OCR tile.
  • The screenshot is gone once used: the image you boxed never enters long-term storage on disk — it lives in memory and passes through the clipboard. The clipboard copy is restored immediately to what you had copied before (your clipboard is not replaced by an image, and no “still there after a restart” trace is left behind). The only thing that touches disk is the temp image mentioned above, overwritten every round and deleted on exit, at most one at any moment. The OCR path never touches the clipboard and leaves no file at all.
  • Selecting a local file path gives you a 📁 on the bar rather than a 🖼 — that's a different feature, see ⑤c File paths.
⑤c File paths: select a path and jump straight to it

When a local path turns up in a chat, in an error message or in a document, select it — the bar gains an extra 📁 icon, and one click opens that location in File Explorer.

  • These shapes are recognized: drive-letter paths (C:\Users\me\a.txt), network shares (\\server\share), relative / absolute paths with forward or back slashes (D:/资料/合同), paths containing environment variables (%APPDATA%\QuickSearch), and file URLs copied out of a browser's address bar (file:///C:/Users/me/a.txt);
  • Selecting too much is fine: if your selection drags in a leading quote or a trailing comma ("C:\a\b.docx"， and the like) it still opens — those marks are stripped off automatically. Windows file names can't end with a dot or a space anyway, so stripping them only makes it more accurate;
  • If it's a file, it gets selected: Explorer highlights that file instead of merely opening the folder it lives in;
  • Failures are reported: a path that doesn't exist, or a drive that isn't plugged in, is stated plainly on the bar — never a silent no-op;
  • Unrecognized is never guessed: a bare bin\tool.exe (no drive letter / UNC / prefix) produces no icon — a wrong guess costs an extra tile on the bar plus an error when you click it, which is far more annoying than “not recognized”;
  • URLs (starting with https://, or with //) are not paths and will not fight with “Open link”.
  • Conversely, selecting a URL gives you the open-in-browser tile (the bar has that built in); selecting an image because you want to search for it is a different matter — see ⑤b Image search.
⑥ Favorites: the text / images you use all day, one click to copy

The “Favorites” page allows up to two levels of folders. Add a top-level folder → give it a name → drop in a sentence, an address or an image you use often.

  • Put it on the bar: give the folder an icon and clicking it on the bar lists what's inside, one click copying one entry;
  • Where a click goes: if the app under the pointer happens to have an input box, the text is typed straight into it; only when there is no usable input box does it fall back to “copy to clipboard”;
  • Dragging: hold the ⋮⋮ handle on the left of a folder to drag it (reorder / nest one level / move back up), and press-and-hold for half a second on a content row to drag it (reorder within this folder / move it to another);
  • Hotkey: assign a combo to “Open favorites” on this page; clicking “Clear” means no hotkey at all;
  • Folder names are locked by default; click “Rename” to change one. “Expand all / Collapse all” only touch the folder levels and never spread the entries into edit mode.
⑦ Hotkeys at a glance (all changeable, all removable)
  • Ctrl+C — summon the bar (can be turned off under “General → Trigger”). Popping up as you copy a selection is its best entry point;
  • Ctrl+Alt+O — start a box selection for text recognition (the whole feature can be turned off on the “Text recognition” page);
  • Open favorites key — record your own; “Clear” = no hotkey at all;
  • Esc — dismiss the bar / leave hotkey recording.

To record a hotkey, click the button and press the combo you want (it has to include Ctrl / Alt / Shift). Changed your mind halfway? Press Esc, or click somewhere else.

Image search has no hotkey for now; enter it from the 🖼 on the bar (see ⑤b). When a local file path shows up on screen, select it and the bar gains a 📁; click it to jump to that path (see ⑤c).

⑧ Backup and restore: land locally first, then go to the cloud

One “Back up now” = write a copy into the local backup folder, then upload that same file to the cloud — the local file and the cloud file share the same name and the same content (config(full timestamp).QuickSearch), so the cloud accumulates one per backup and you restore whichever one you want. File names are not your problem: whatever it's called locally is what it's called in the cloud.

  • WebDAV: Nutstore / Nextcloud / Synology all work. Enter only the root address; the app appends the folder itself and creates it as needed. On Nutstore use an “app password” rather than your login password;
  • Encryption: once a backup password is set, every backup (cloud upload and local export alike) is AES-256-GCM + Argon2id encrypted and no plaintext is visible inside the file. Lose the password and it cannot be opened;
  • Automatic: you can turn on “Sync on startup” (compare the newest cloud copy with this machine and take the newer) and “Sync on exit” (push one copy before quitting). Both only upload when the configuration actually changed — otherwise every launch would add a cloud file even with not a single character edited;
  • Restore: “Restore from cloud” lists every cloud backup; pick one. A snapshot is taken locally first, so a wrong restore can still be undone;
  • Cleanup: “Keep the latest 10 only” clears local and cloud together, keeping the newest 10; to delete selectively, click “Manage” at the top right of the cloud list and every backup becomes checkable — tick them and click “Delete selected”;
  • What a backup holds: every setting and appearance option, the engines on the bar and their order, custom icons, the whole favorites tree, OCR keys, WebDAV credentials and hotkeys — restoring on another computer restores all of it.
⑧b Plain-text import / export: hand over only the parts you pick

This is a different thing from ⑧ Backup; don't mix the two up:

  • Backup (.QuickSearch) = the whole configuration, encryptable, restored by overwriting everything — use it for a new computer or a reinstall;
  • Plain-text export (.qsconf) = a few chosen items, unencrypted, imported by overwriting only those items and leaving the rest alone — use it to hand a colleague a set of settings.

On the “Data” page click “Export”, then tick what you want:

  • Only non-private items are ticked by default: engine configuration, app settings, icons and image search are on; API keys, favorites and backup settings are not ticked by default — glance at what's ticked before sharing, and don't send anyone your keys;
  • The button then reads “Export 3 items…” according to what's ticked; with nothing ticked it opens no dialog (there's nothing to export, so it doesn't bother you);
  • The exported file is plain JSON that Notepad can open and edit, unencrypted — which is exactly why it can be sent to someone else to import, and exactly why you shouldn't move passwords with it;
  • Import merges: only the items present in the file are poured back, and your current favorites and hotkeys are not touched by a single character. The flip side is that using it to “restore the scene” will not delete what you have extra right now — for a full overwrite take the ⑧ Backup route;
  • Plain-text import only accepts plain-text exports: feeding it an encrypted backup (or a whole backup file) is rejected outright, with a pointer to the “Backup” page — the two routes each do one job, and “import” never quietly turns into “full overwrite”.
⑨ Tray icon and quitting

Double-click the tray icon = open the settings window directly (a single click does nothing — the tray sits next to the clock, and a stray click popping a window is annoying).

Right-click the tray icon = menu: open settings, back up now, start recognition, quit.

To quit for good, click “Quit” in the tray menu — closing the settings window does not exit the app, which stays in the background waiting for your next selection.

⑩ Where all my data lives
  • Configuration: %APPDATA%\QuickSearch\config.json (the backup folder can be moved elsewhere);
  • Replaced icons: %APPDATA%\QuickSearch\icons\;
  • Backups: the rolling backup config.auto(timestamp).QuickSearch, the pre-restore snapshot config.before-webdav(timestamp).QuickSearch, and the one you drop by clicking “Back up now”, config(timestamp).QuickSearch (same name as in the cloud).
  • The plain-text configuration you export (.qsconf) goes wherever you choose; the app never stuffs it into the data folder — how to export selectively and how to share it is covered in ⑧b Plain-text import / export. Whoever you decide to send that file to is who ends up responsible for it.
  • Image-search screenshots and OCR screenshots are temporary: discarded once used and never left on the disk (except for the three “image URL” engines in image search — there the public link is one you supplied and the app merely opens it).

Sharing it with someone is safe: the app itself contains no account information — OCR keys and WebDAV credentials are written only into the local config.json, travelling with your configuration rather than with the app. Whoever receives it gets a “clean” program.
